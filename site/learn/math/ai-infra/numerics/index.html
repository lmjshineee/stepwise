数值计算：公式相同，为什么结果不同

通过真实 float32 舍入、条件数和稳定统计，解释数学公式与计算结果之间的差别。

课程AI Infra数学基础conceptual
开始自测
建议先读向量与矩阵从 logits 到分布

(a+b)+c 与 a+(b+c) 在实数里相等，为什么换一种归约顺序后，程序结果可能不同？因为真实计算保存的是有限个可表示数，运算中不断发生舍入。

本篇统一观察小规模 CPU 示例；不把浏览器 Number 当作 FP16，也不根据数学相等就要求两份实现逐位相同。

精度与动态范围是两件事

浮点数用符号、指数和有效数字表示数值。指数帮助覆盖不同数量级，有效数字决定同一数量级附近能分多细。离零越远，相邻可表示数之间的绝对间隔通常越大，因而不能理解成“所有数都保留固定小数位”。

FP16 与 BF16 同为 16 位存储，但指数与有效数字的分配不同。BF16 的动态范围较大，不代表任意数都更精确；选格式要同时看范围、误差和实际算子支持。

一个特别直观的例子是 float32 在 10810^8108 附近的间隔为 8。加入 1 后仍可能舍入回 10810^8108，这个小项不会因为后面再做减法就自动回来。

先分清问题敏感，还是计算路径脆弱

对可逆矩阵，二范数条件数可写为 κ2(A)=σmax⁡/σmin⁡\kappa_2(A)=\sigma_{\max}/\sigma_{\min}κ2​(A)=σmax​/σmin​。diag(1,0.001) 的条件数是 1000：不同方向的尺度差异很大，某些输入扰动可能被显著放大。它是问题敏感性的指标，不是一次运行已经产生了千倍误差的结论。

算法稳定性则关注实现有没有额外放大误差。两个接近的大数相减会丢掉很多有效位；先算 E[X2]−E[X]2E[X^2]-E[X]^2E[X2]−E[X]2 求小方差时尤其明显。换成较高精度可能缓解舍入，但不能凭更换 dtype 消除问题本身的病态。

按偏差更新，避免先形成两个巨大量

Welford 方法保存当前数量、均值和偏差平方累计量，而非一开始就相减两个巨大的二阶量：

对 [10⁹+1,10⁹+2,10⁹+3]，总体均值为 109+210^9+2109+2，总体方差为 2/32/32/3。函数最后除以 nnn，计算的是这组数的总体方差；若要估计总体方差的无偏样本估计，分母和适用条件需要另行说明，不能只改名字。

代数等价的公式，也有更合适的浮点路径

Softmax 一篇已经推导统一平移不改变概率。数值上，把最大 logit 减掉再算指数，可以避免直接计算 exp(1000)；需要对数概率时，直接计算 log-softmax，省去先下溢成 0 再取对数的损失。

类似地，长归约可以采用分组、配对或补偿累加等方法减少某些误差，但具体保证依赖算法和输入。更改并行树或分块方式后，结果不逐位相等不一定是错误，仍需与独立参考和任务容差比较。

数值稳定与系统优化有时能同时改善：避免不必要的中间量，既可能减少舍入路径，也可能减少搬运。它们并非永远一致，不能用“更稳定”直接代替性能测量。

混合精度要逐项说明谁用什么精度

一次计算至少要区分输入格式、内部乘加／累加路径、输出格式、参数与优化器状态。输入是 BF16，并不能单凭这一点推断内部一定怎样累加；框架策略、算子和硬件都要核对。

Loss scaling 的基本思想是先把损失乘 SSS，让反向中的小梯度可能落入可表示范围，之后再除回 SSS。如果中间量已经溢出或梯度已经下溢丢掉信息，事后乘回来不能恢复。缩放本身也可能过大，需要检查非有限值并明确更新策略。

小结：同时检查问题、算法与表示

浮点格式限制可表示数，算法决定运算顺序，问题条件决定输入扰动有多敏感。实数公式、代码实现和硬件路径要逐层核对；一个正确的误差比较，需要独立参考、明确 dtype 和有理由的容差。
