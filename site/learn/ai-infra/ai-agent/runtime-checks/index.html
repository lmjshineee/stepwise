建议先读接入模型与资料工具

资料问答 Agent 已能调用模型、搜索和读取，但“有最终文字”并不意味着任务完成。它可能反复搜索同一个词，读不到资料却编出引用，或者引用了一条真实资料，结论却与正文相反。

这一篇不增加新工具，而是给已有程序建立可观察的停止条件和失败实验。仍使用配套项目，先执行离线检查，再把真实模型评估单独看待。

先给失败起名字，再决定谁来处理

工具参数错误往往可以修正。例如读取不存在的 ID，模型下一轮可以根据错误改用搜索结果中的 ID。HTTP 请求失败则是另一层的问题：工具尚未执行，反复把异常文字交给模型并不能修好网络。

现象本项目的处理为什么这样处理
JSON 错、参数多余、ID 不存在作为 ok:false 的工具观察回传模型可以改请求，宿主仍计入调用次数
同一个调用 ID 再次出现protocol_error，停止无法继续保持清楚的请求／结果身份
HTTP 错误、网络超时、响应未完成固定错误状态，停止不输出原始敏感响应，不自动无限重试
模型轮数、工具总数或上下文超限对应预算状态，停止不让任务以为还在正常推进
最终文字没有有效已读来源标记unverified_answer不能仅因为模型结束就称作完成

以后若加入重试，要先解释重复执行的后果。重复读同一条资料与重复提交订单不同；不能给所有工具统一套一个“失败再试三次”。本项目保持只读，也仍然通过预算防止没有进展的重复。

用不同单位限制不同开销

项目的限制记录很小，完整定义如下：

turns 是最多调用模型几轮，calls 是整个任务最多执行多少次工具。一轮模型响应可能包含多个请求，所以不能只用一个计数器。context_chars 是发送之前，序列化消息文字的长度；它不是 token 数，也没有包含全部请求开销。

默认 6 轮、6 次工具、24000 字符，是让小实验有边界的选择，不是通用生产参数。单次模型输出的 2048 token 限制在适配层，HTTP 的 30 秒设置用于阻塞 I/O。它们分别限制不同对象，不能据此算出精确总费用或承诺任务必在 30 秒内结束。

留下执行记录，不把所有内容都记下来

轨迹是为了回答“哪一轮调用了什么、工具是否成功、为什么停止”。它不是隐藏推理的转储，也不必包含用户问题、资料全文和 HTTP 请求。

真实运行也遵循相同记录结构。项目不把参数、资料正文、模型原始输出或密钥写入轨迹；--trace 是显式选择的本机文件。轨迹写入失败，CLI 会用退出码 2 报告失败，不宣称已保存。

这份小轨迹足够查调用顺序，却不能独立还原模型当时所有输入；因此它不是完整重放档案。离线重放使用另外准备的固定响应 data/replay.json。如果今后要保存真实会话用于复现，需要另行设计数据范围、脱敏和模型不确定性的记录，不能直接把所有对象打印到日志。

检查引用，但不把引用当成正确答案

最终文字的检查依赖 read_ids：只有工具成功读取的记录才进入这个集合。宿主提取形如 [release] 的标记，要求至少一个，并且全部属于已读记录。没有标记或出现 [missing]，得到 unverified_answer。

这能发现编造来源身份，却不能自动判断结论是否由资料支持。配套测试特意构造一个反例：

资料明确说“构建通过只说明产物可以生成”，这个答案却说“保证没有缺陷”。[release] 确实来自已读资料，所以机械检查仍会返回 complete。这里的 complete 只表示执行协议和引用门槛通过，不能翻译成“事实已核验”。

人工检查应分开问：是否完成了用户任务？资料是否支持每个关键判断？有没有省略条件或把资料意思说反？预算和轨迹也各自记账，不要把一次工具成功、一次程序退出码 0 或一次引用命中叫作模型准确率。

故障资料 untrusted 还有另一种边界：正文要求执行 Shell，也不会让 shell 自动进入白名单。测试故意让模拟模型请求 shell，验证宿主返回 unknown_tool。它证明执行器没有这项能力，不能证明真实模型永远不会被资料诱导，也不能代替更广的提示注入评估。

用固定失败输入检查程序，再评估真实模型

运行项目自带检查：

测试包括工具观察到达下一轮、不透明推理项保留、错误 ID 后修正、非法参数、重复调用身份、预算、轨迹内容、越权工具、网络与不完整响应。它们检查的是程序在指定输入下的行为；测试全部通过，并不说明模型会选择正确的工具。

再做一个会让检查失败的改动：暂时注释 agent.py 里把工具观察追加到 messages 的语句。重新运行测试，test_tool_result_reaches_next_model_call 应报错。恢复代码后再跑一次，让你确认测试确实约束了这条消息通路，而不是只检查“脚本没退出”。

真实模型需要独立任务集。例如正向问题“发布前还要检查什么”、缺资料问题“下周天气怎样”、包含越权资料的问题，都要记录实际模型 ID、问题、执行轨迹、调用量和逐项人工判断。固定回放能重现程序分支，不能替代这些真实试验。本批项目提供模型连接方式，实际外部模型表现以另外的运行记录为准。

这三篇已经把请求、工具、反馈、停止和检查连成一个可运行项目。后续路线再扩展任务拆解、上下文选择、审批写入和中断恢复；这些能力尚未实现时，先让它们作为未完成节点保留，不用更多术语掩盖已有程序的边界。
