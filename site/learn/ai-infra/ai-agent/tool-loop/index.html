从零写出 Agent 的工具调用循环

用一个可运行的 Python 程序，分清模型请求、宿主执行和工具结果回传。

教程AI AgentPython工具调用动手实现
开始自测

你问“构建通过就能发布吗？”，模型也许立刻写出一段建议。但如果任务要求根据一份资料回答，关键不在于建议听起来是否合理，而在于程序有没有真正读取资料、把结果交回模型，再形成答案。

这条路线要做一个资料问答 Agent：它可以搜索公开资料、按 ID 读取内容，再引用资料回答。先用 Python 写清执行过程，接着接入真实模型，最后用失败实验检查边界。你需要会写函数、列表和字典；本例只用 Python 3.11 及以上版本的标准库，不需要先学习模型训练。

先让一次读取真实发生

Agent 在这里指一个能根据任务和环境反馈选择下一步动作的程序。选择动作的是模型，真正执行动作的是宿主程序，也就是我们将要写的 Python 代码。工具则是宿主允许模型请求的操作，例如“按 ID 读取一条资料”。

先把问题缩小：资料暂时只有一条，模型只可能请求一次读取。工具结果到达之前，程序不能拿模型猜测的内容当作读取结果。

图中有两条不同的路径：模型给出最终文字时可以结束；模型提出工具请求时，宿主必须执行工具，并把实际结果送回去。宿主也可以因为预算或协议错误停止。不能因为模型写了“读取成功”，就跳过执行这一步。

固定写好“先搜索、再读取、最后回答”的程序属于预先安排的流程。模型根据反馈决定是否换关键词、读取哪条记录或结束，才增加了这里要研究的 Agent 行为。本篇先做循环的测试装置，下一篇才把固定响应换成真实模型。

用三种消息写清一次往返

消息是一次运行保留下来的输入和结果。用户消息说明任务；工具调用消息说明想做什么；工具结果消息说明实际发生了什么。

消息谁产生本例的重要字段
用户问题调用者role=user、问题文字
工具调用模型或测试替身name、JSON 字符串形式的 arguments、call_id
工具结果宿主type=function_call_output、同一个 call_id、结果字符串
最终文字模型或测试替身消息内容中的 output_text

call_id 是这一次调用的身份，不是资料 ID。模型可能两次调用同一个工具：第一次读 release，第二次读 budget。工具名相同，调用身份仍然不同；回传结果时要指向对应的那一次请求。

这里的 JSON 是跨边界传递参数和结果的文字格式。json.loads 把文字还原成 Python 值，json.dumps 则把值编码为文字。解析成功只说明格式能读，不代表参数符合工具要求；后面仍要检查名称和允许的资料 ID。

choose(messages) 产生一次响应，响应中有工具调用就继续处理；没有工具调用时，取出最终文字并返回。messages.extend(output) 保留请求本身；messages.append(...) 再保留真实工具结果。下一次选择动作时，输入同时包含“之前想做什么”和“实际上读到了什么”。

本例把唯一资料放在字典里，notes[args["id"]] 确实执行了读取。replay 则是测试替身：第一次固定请求 release，之后读取刚刚回传的观察，拼出最终文字。它不理解你的问题，也不会自主决定换资料；换一个问题，动作仍然一样。这样安排是为了先检查宿主消息循环，不把测试响应误认成模型能力。

循环最多执行三轮，超过后抛出错误。这个例子的正常路径只要两轮：第一轮请求并执行工具，第二轮生成文字。轮数与工具调用数不同；一轮响应原则上还可能包含多个工具请求，后面的实现会分别计数。

故意破坏回传，再解释失败

先预测再修改：把 messages.append 所在的结果回传语句删掉，保留前面的工具读取。程序还能输出最终答案吗？

不能。下一轮 replay 看到的最后一项仍然是工具请求，因而报告 missing tool observation。工具已经在宿主内部运行过，但“内部有结果”和“模型下一轮看到了结果”是两件事。

再恢复代码，把回传的 call_id 改成 wrong。这次有结果，却不能确定它属于正确请求，测试替身会报告 tool observation belongs to another call。不要只用一个字符串变量覆盖“最近结果”，否则两个相似调用很容易配错。

本篇对未知工具或非法 ID 直接抛异常。这适合看清最小路径，但还不适合面对会生成各种参数的模型。下一篇把白名单、参数检查和错误结果放进独立工具层；错误能否修正、何时停止，在第三篇用实验区分。

小结：先写清谁决定、谁执行、谁反馈

工具循环不是让模型自己写一段“我已执行”的文字。模型提出请求，宿主检查并执行，真实结果按调用身份回传，模型才能根据观察继续。保留下来的消息既影响下一步选择，也让我们有办法检查发生过什么。

现在已有可运行的宿主骨架，还没有一个会自主选工具的模型。继续接入真实模型与资料工具，保留这条消息往返路径，只替换产生动作的一层。
