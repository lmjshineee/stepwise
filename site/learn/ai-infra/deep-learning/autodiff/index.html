计算图与梯度：手写一次线性层反向

手算共享路径梯度，再用 NumPy 与真实 PyTorch 对照线性层反向和梯度模式。

建议先读向量与矩阵微积分

同一个变量既参与乘法，又直接加入结果，反向时为什么要把两条贡献相加？先手算一张小图，再把它推广到线性层；自动微分负责组织这些局部计算，不是替模型决定更新步长。

本篇是深度学习路线中原有自动微分节点的正式入口。数学路线只链接到这里，不另写第二份同题课程。先读局部变化与积分以及矩阵乘法，即可跟上下面的数值。

先确定函数、参数和目标

输入输出的轴，要先于求导确定

模型把输入映射到预测，例如 Y=XW+bY=XW+bY=XW+b。这里按行保存样本，X[B,D]、W[D,H]、b[H]，预测是 Y[B,H]。对谁求导，取决于谁需要变化：训练通常要参数梯度，检查输入敏感性时也可能要输入梯度。

表达能力来自函数组合

单个线性层只能表达仿射关系；把非线性运算与线性层组合，才能描述更丰富的函数。增加层数并不改变链式法则，但会增加需要组织的运算路径与中间量。

可学习的部分是参数，不是函数名字

写成 f(x;θ)f(x;\theta)f(x;θ)，xxx 是输入，θ\thetaθ 是可调整参数。一次前向使用当前参数计算预测，损失把预测和目标比较成标量。只有明确这个损失，才能讨论“梯度在改善什么”。

选读：把模型、学习与网络几个名字放回各自位置

优化器使用梯度，自动微分提供梯度

自动微分算 ∇θL\nabla_\theta L∇θ​L；优化器再根据学习率、历史状态等更新参数。算出了正确导数，不代表所选步长合适，更不代表已经学到了可泛化的规律。

网络在程序里是一组相连的运算

计算图的节点是运算结果，边描述依赖关系。使用这个视角不需要把每个节点类比为生物神经元；同一变量流向不同算子，正是后面梯度汇合的来源。

多层组合增加路径，也增加保存成本

反向需要的某些局部导数依赖前向值，例如平方需要知道输入。层数增加时，这些保存量可能成为训练内存的重要部分；能否丢掉再算，属于重计算策略，而非把梯度关闭。

参数、缓冲与运行状态不要混为一谈

可训练参数、累计的梯度、模块中的统计缓冲具有不同职责。改变评估模式不自动清空梯度，清空梯度也不等于把参数恢复到初值。

不同任务复用同一种局部求导机制

分类与回归可以选择不同目标，但只要计算由有明确局部导数或导数约定的运算组成，就能组织反向。某条离散选择不可导时，框架不会凭空补出普通导数。

先写出真正被优化的标量

同一批误差取 sum 还是 mean，会改变梯度尺度；有 mask 时还要说明分母是样本数、元素数还是有效 token 数。先定目标，再判断梯度，避免把不同损失误当同一实验。

沿同一张图前向，再反向

梯度收集各输入方向的局部变化

多变量标量函数的偏导，表示固定其他输入时沿一个坐标改变的局部变化。把各偏导放在一起形成梯度。对可微函数，ΔL≈∇LTΔx\Delta L\approx\nabla L^T\Delta xΔL≈∇LTΔx；在欧氏长度约束下，负梯度给出局部最陡下降方向，有限步长仍需另外选择。

共享输入意味着有多条影响路径

取 a=xya=xya=xy、b=a+xb=a+xb=a+x、L=b2L=b^2L=b2。在 x=2,y=3x=2,y=3x=2,y=3 时，前向依次得到 a=6,b=8,L=64a=6,b=8,L=64a=6,b=8,L=64。x 一次经乘法进入 a，另一次直接进入 b。

反向传递的是上游影响乘局部导数

从 ∂L/∂b=2b=16\partial L/\partial b=2b=16∂L/∂b=2b=16 开始。加法对两个输入的局部导数都为 1，所以给 a 的贡献为 16，直接给 x 的贡献也为 16。乘法对 x 的局部导数为 y=3y=3y=3，再给 x 贡献 48；因此

∂L∂x=16+48=64,∂L∂y=16×2=32.\frac{\partial L}{\partial x}=16+48=64,\qquad \frac{\partial L}{\partial y}=16\times2=32.∂x∂L​=16+48=64,∂y∂L​=16×2=32.

如果把一条路径的结果覆盖成另一条，而非相加，就丢失了真实影响。图上的累加与“多次 backward 跨步骤累积到同一缓冲”是两回事，后面会再区分。

局部规则由前向依赖决定

不必为所有参数逐个重新运行整个模型。反向按依赖顺序复用已经求出的上游贡献，乘局部导数，并在共享节点相加。这是链式法则的程序化组织。

把小图推广到真实张量

动态图记录本次实际执行的运算

PyTorch 在普通梯度模式下记录依赖可求导输入的运算。Python 分支走了哪条路径，图就描述本次的这条路径；它不预先证明其他分支正确。原地修改可能破坏反向需要的前向值，因此不能把省下一个张量简单当成安全优化。

backward 写入的是叶子张量的梯度缓冲

叶子参数通常通过 .grad 接收累计梯度。第一次对 x=2 的平方求导得到 4；用同一个叶子做一次新的平方前向，再 backward，缓冲可能变为 8。需要新一步的梯度时应按训练流程清空，而不是以为每次 backward 都自动覆盖。

同一张已释放必要中间量的图，不能不加处理反复 backward。重新前向、保留图或采用更合适的求导接口要按用途选择；不要为了消除错误就全局开启 retain_graph=True。

向量输出需要先指定怎样汇总

y=x*x、x=[1,2] 得到两个输出。它没有唯一的“总梯度”，要给上游向量或先形成标量损失。上游 [3,4] 对应 3y0+4y13y_0+4y_13y0​+4y1​，对输入的梯度为 [6,16]。不指定上游，直接对普通非标量输出调用 backward 会被拒绝。

高阶导数需要保留求导过程的可求导计算

例如 x3x^3x3 在 2 的一阶导为 12，二阶导也为 12。使用 PyTorch 继续对一阶结果求导，需要在第一次求导时按用途设置 create_graph=True；这与只为再次反向保留前向图的 retain_graph 不同。高阶图也有内存成本，基础训练不应无条件开启。

VJP 把上游向量穿过局部运算

Jacobian 收集向量输出对向量输入的所有偏导。实际反向通常计算上游向量与 Jacobian 的乘积，即 VJP，而非显式创建巨大矩阵；正向模式对应 JVP，选择与输入、输出规模及任务有关。

对线性层 Y=XW+bY=XW+bY=XW+b，给定上游 G=∂L/∂YG=\partial L/\partial YG=∂L/∂Y，有

dX=GWT,dW=XTG,db=∑iGi,:.dX=GW^T,\qquad dW=X^TG,\qquad db=\sum_iG_{i,:}.dX=GWT,dW=XTG,db=i∑​Gi,:​.

dX 与 X 同形，dW 与 W 同形，bias 复用于每个样本，所以 db 沿 batch 归约。本例损失为 12∑(Y−T)2\frac12\sum(Y-T)^221​∑(Y−T)2，上游恰好是 Y-T；若改成 mean，还须加上相应分母。

遇到零点、detach 和非叶子时检查接口约定

ReLU 在零点不可微，框架使用既定导数约定，不能要求中心差分恰好与它相同。detach() 切断求导关系，但不承诺复制存储；非叶子张量的 .grad 默认也未必保留。需要观察中间梯度时，明确使用相应保留或求导接口。

反向的 shape 也要逐轴解释

线性层反向主要包含两个矩阵乘法和一个归约。公式与算子能对上之后，才进入融合、内存和设备优化；本篇不提前完成高效 attention 或训练并行的后续节点。

图记录、梯度缓冲和评估模式分别控制

普通梯度模式决定是否记录依赖

运算是否参与反向，取决于输入要求与当前模式。关闭记录不是删除参数，也不是清空已有 .grad。

no_grad 临时关闭普通运算的反向记录

在 with torch.no_grad(): 中，普通的 x*x 不记录反向。退出上下文后恢复原模式。它并不普遍重写所有张量的 requires_grad：显式接收该参数的工厂函数等有自己的规则。

enable_grad 可以在局部重新开启

外层 no_grad、内层 enable_grad 时，只有内层相应运算重新记录。上下文负责退出恢复，避免手写全局开关忘记还原；set_grad_enabled(training) 可把此选择连接到明确的布尔状态。

inference_mode 有更强的张量限制

纯推理模式还省去一些视图追踪与版本计数工作；其中创建的推理张量不能在外部直接随意改成需要梯度的张量，也不能随意混入需保存它供反向的操作。要按接口用途选择，而非只把它称为“更快的 no_grad”。

eval 改模块行为，不代替梯度模式

model.eval() 改变 Dropout、BatchNorm 等模块的行为，但不会自动禁止求导。本项目实际检查 eval 下的 Dropout 输出仍可要求梯度；模式切换不应与清空缓冲或关闭记录混为一谈。

用真实调用验证状态差别

函数同时检查梯度缓冲累积、关闭与重新开启记录、eval，以及推理张量在外部开启梯度时被拒绝。它们分别对应不同条件，不用一个“训练开关”代替全部状态。

从手算走到可核对的程序

共享路径相加，再向前一层传播

用更小的 z=x2+xz=x^2+xz=x2+x 检查同一规则：x=2x=2x=2 时两条贡献为 4 和 1，总梯度为 5。这个简单例子适合排查“写回时覆盖了前一条贡献”的错误。

有限差分是一条独立的小规模对照路径

项目用 float64、固定小矩阵，把手写 dW 与逐元素中心差分比较，再对照 PyTorch 自动微分。不要在不可微点或随机变化的函数上期待相同检查结论。

小结：正确梯度是后续系统工作的一条基线

反向把上游影响乘上局部导数，在共享路径汇合；张量实现还要检查 shape、归约与损失分母。得到正确参考后，再讨论保存激活、重计算和融合成本。该参考程序验证小模型的数学与接口，不代表完整训练任务已经验证。
