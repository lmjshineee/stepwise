测量之后再优化：时间、内存与性能定位

先验证数值，再记录预热、重复、分位数和内存范围，用实际 CPU 数据定位瓶颈。

教程AI InfraPythonpractical
开始自测
建议先读NumPy 与 PyTorch数据怎样喂给模型并发与异步概率与统计

把 Python 循环改成 NumPy 后，看到一次耗时变短，是否就能宣布优化成功？先检查结果是否一致，再明确计时是否包含准备、搬运、同步与输出，最后看重复样本，而不是只看一个最好看的数。

本篇在同一个 CPU 小项目上比较完整批调用。图中数据来自本次实际运行，但样本很少，只服务于理解测量流程，不用来预测你的机器、GPU 或在线服务的尾延迟。

先固定问题，再选择计时边界

工作负载是 float64 的 (16,12) @ (12,8)，输入用固定种子生成。一条实现用普通 Python 列表循环，另一条用 NumPy 矩阵乘；输入转换在计时前完成，因而计时不包含这一次转换。

先用独立数组结果和容差确认正确。若某个快版本漏掉了尾部、改变 dtype 或改用不同输入，就已经不是同一比较；不能等跑完 benchmark 再补一句“结果差不多”。

记录至少包括 shape、dtype、方法、环境、预热、重复次数和每次处理量。若计入启动与转换，就明确写“端到端”；若只测算子，也不要把数字包装成用户请求延迟。

预热与重复是为观察波动，不是挑最好看的样本

使用 perf_counter_ns 观察单调高分辨率经过时间；对很短操作，在同一计时段里执行多次，再折算每次。预热帮助减少首次初始化等影响，但不保证之后永远稳定。

这里每种方法先预热 2 次，记录 7 组、每组 3 次，单位最终为毫秒/完整批调用。内层分组会平滑某些波动，所以这些样本不是 21 个独立在线请求，不能拿它们估算服务 P99。

CPU 提交耗时不能代替设备完成耗时

加速设备上的操作可能异步执行。只量主机发出调用到返回的间隔，可能主要量到提交工作。需要按设备和框架支持，使用适当同步边界或设备事件，同时说明数据搬运是否计入。

本项目不包含未经该设备验证的 CUDA/MPS 性能代码，也不把 CPU 的计时路径换个标签叫 GPU benchmark。未来要测设备版本，须在对应设备重复正确性与计时检查。

吞吐、典型延迟与尾延迟分别说明

吞吐是单位时间完成多少工作；本例把每批 16 行除以中位批调用时间，只得到一个按中位数折算的行/s 指标，不是并发服务的完整吞吐测量。

P50、P95、P99 是分位数。本项目采用 nearest-rank：将 nnn 个样本排序，取第 ⌈pn⌉\lceil pn\rceil⌈pn⌉ 项。只有 7 个样本时，P95 与 P99 都会落到最大样本，不能据此认为尾部估计已经可靠。

切换方法时纵轴重新缩放，先看标注的毫秒数再比较。图表显示采样条件和环境；它不是未来运行的承诺，也没有把低样本量隐藏在平滑曲线后面。

时间知道花在哪，内存也要认清范围

cProfile 可以观察 Python 函数累计时间与调用次数，适合定位调用层的热点；原生算子内部、设备执行与等待需要相应工具。可从项目目录运行 python -m cProfile -s cumulative -m infra_lab.measure，先找占比，再决定要改哪段。

PyTorch profiler 可进一步观察算子和支持的设备活动，但 profiler 自身会引入开销。详细归因实验与最终性能计时应分开，避免把插桩成本当成业务本身的延迟。

本项目用 tracemalloc 观察一次调用的被追踪分配峰值。覆盖原生分配的范围取决于库的集成，它不是进程 RSS，更不是 GPU 显存峰值。NumPy 的 nbytes 又是逻辑元素字节数；这些数字回答的问题不同，不能合并成一个“内存占用”而不说明口径。

把正确性、条件和原始样本一起留下

在完整项目运行 python -m infra_lab.measure，输出一份 JSON 报告。当前页面的原始公开记录可从CPU 实验数据下载。

完整文件：infra_lab/measure.py

报告保留各组样本，不只保留最小值。再次运行应允许耗时变化；测试断言字段、样本数量、结果正确和时间有效，不断言“这台机器必须快几倍”。没有预先确定合理统计规则时，不为了好看删掉慢样本。

下一次修改可分别比较 batch、数据复制、向量化或并发上限，每次先写预期影响，再观察数据。如果没改善，也记录原因：输入太小、启动成本、复制占主导、内部线程争用，都可能使直觉失效。

小结：一份性能结论需要可重跑的上下文

先保证相同任务与正确结果，再固定计时边界，保留环境、原始样本和统计口径。用 profiler 解释成本，用重复测量评估变化；把教学模型、CPU 实验、设备实测和真实服务指标分别陈述，结论才有可用范围。
