CS106L：从可运行程序到对象与资源

沿类型、标准库、对象与资源推进，配合七次作业与逐章自测建立可解释的 C++ 基础。

课程C++CS106L语言基础资源管理C++23
开始自测
本篇的学习目标先运行程序，再学类型与引用、容器与输入、类与资源，逐步完成日志统计；泛型、继承与并发按任务扩展。

先能运行，再能解释对象为何这样变化

一段程序能算出结果，只是开始。记录越来越多时，怎样组织数据？把函数交给别人调用时，谁能修改对象？函数提前退出时，文件和内存由谁清理？CS106L 把这些问题串成标准 C++ 的主线。

读完这组基础文章，你应能完成小型数据处理程序，并逐行解释它的对象、借用和释放责任。课程假设你已认识变量、条件、循环和函数；不要求先背熟复杂模板。完整程序统一给出 C++23 编译方式，相关特性旁另标首次引入版本。

标准 C++ 的基本视角

三条线索可以用于阅读任何示例：类型决定允许什么操作，对象寿命决定什么时间可以访问，所有权决定谁负责释放资源。

例如 auto copy = items 保存一个容器副本，auto& alias = items 绑定原容器。两种声明都合法，但修改目标不同。学习时不仅判断“能否编译”，也要解释“程序实际修改了谁”。

从标准库入手

保存一组数值先用 std::vector<int>，保存文本先用 std::string，管理独占动态对象先用 std::unique_ptr。这些类型负责自己的内存，调用者先学习其操作与失效规则，再考虑自行管理底层资源。

例如 std::vector<int> scores{70, 90} 描述拥有两个分数的容器，而不是两个需要手动释放的指针。后面学习类与资源时，再解释这种“对象结束即释放资源”的机制。

基础主线：先回答三个具体问题

你要回答的问题学习内容学会后能解释的行为
我操作的是原对象，还是副本？类型、初始化、引用、const修改循环变量为什么有时不改变容器元素
怎样把数据与处理逻辑分开？流、容器、迭代器、模板、Lambda同一统计算法怎样接受文件或字符串输入
谁负责让资源最终被释放？类、复制、移动和资源获取即初始化（RAII）文件如何在函数正常返回或异常离开时都被关闭

第一轮按下面的顺序完成一个小任务，再继续下一步。继承、并发、协程和模块是后续按需扩展，不是开始处理输入前的门槛。资源获取即初始化（RAII）把资源交给对象管理：对象在正常离开作用域或异常栈展开时析构，从而释放资源；直接终止进程不保证执行这些局部对象的析构。

学习顺序

按首页顺序推进即可；基础分为两个阶段：

阶段顺序与阅读入口完成标志
类型与标准库编译 → 类型 → 引用 → 流 → 容器 → 迭代器能读入、保存并查找数据，解释边界和失败
对象与资源类 → 选读继承 → 模板与const 接口 → Lambda → 运算符 → 特殊成员 → 移动 → optional → RAII → 构建能保持类的合法状态，解释复制与转交，完成多文件构建

继承练习是可选分支；不用先完成它才能学习模板。课程第 17 讲 Iceberg 是扩展视野的选读，不把其中展示的实验性接口当作基础程序的依赖。

章节之间依赖什么

把各章联系起来，应沿具体依赖理解。类定义对象保存什么状态；六个特殊成员函数决定初始化、复制、移动与析构如何发生；引用和值类别影响这些操作怎样被选择。模板把同一规则用于不同类型，Ranges 再把通用操作组织为数据处理链。

因此，看到移动构造前先问“对象拥有哪项资源”，看到视图前先问“它借用了谁”，看到模板约束前先问“算法实际要求哪些操作”。章节链接用于定位这些问题的完整解释，不需要先背一串新特性名称。

按接口问题定位章节

基础完成后，可以按任务回查下面接口：

  • 自己定义值对象：类、构造与值语义，以及特殊成员函数的生成规则。
  • 判断声明和调用行为：类型系统、移动语义。
  • 表达资源责任：RAII 与智能指针，以及继承和多态中的基类析构。
  • 复用处理规则：模板与编译期计算（后续专题，未完成）、Ranges 与视图（后续专题，未完成）。
  • 处理工程边界：错误接口（后续专题，未完成）、并发与内存模型（后续专题，未完成）、模块与构建（后续专题，未完成）。
  • 检查反例：实用易错清单（后续专题，未完成），将现象对应到具体类型、寿命和版本规则。

用一个行为连接相邻章节

把一条具体依赖说清，比画出所有名词的连线更有用。例如：引用章说明别名，容器章说明存储迁移，两者合起来才能判断“扩容之后旧引用还能不能用”。特殊成员说明对象能做哪些复制与移动，RAII 才能进一步组合出可靠的释放责任。

回查时先定位自己的问题，再选择相邻章节；首页路线负责整体顺序。

C++11 奠定的现代写法

这些机制并不互相代替：auto 根据初始化表达式推导类型；范围循环描述遍历；Lambda 保存可调用规则及捕获的状态；移动语义处理可转交的资源。比如 for (auto score : scores) 遍历副本，for (auto& score : scores) 可以修改元素——更短的声明仍然需要说明对象关系。

值、观察与借用是不同接口

“现代写法”的共同点，是把数据和责任写进接口。传入 const std::vector<int>& 表示观察既有容器，返回 std::vector<int> 表示交付拥有结果的值；返回借用视图则要求明确底层数据寿命。选择哪种形式，首先由调用者需要什么决定。

现代接口：从实际问题选择 C++20/23 特性

读完类型、容器、类和资源寿命以后，再按实际接口问题进入扩展：

  1. 模板只接受某类输入，用概念约束（后续专题，未完成）写明前提。例如整数求和函数拒绝字符串，而不是到函数体深处才报错。
  2. 组合筛选、变换和遍历，用Ranges 与视图（后续专题，未完成），同时检查借用的数据能活多久。
  3. 调用需要区分多种失败原因，用成功或错误结果（后续专题，未完成）保存结果；严格解析端口时，格式错误和数值越界是不同分支。
  4. 把这些接口组合成日志统计程序（后续专题，未完成），验证坏行、空输入与文件打开失败。

线程、协程和模块随后分别进入并发（后续专题，未完成）、协程（后续专题，未完成）与Modules（后续专题，未完成）。先说明共享状态、暂停后寿命和构建边界，再使用对应语法。

选读速查：C++23 扩展的用途与前提

C++23 的扩展应按需要解决的问题阅读，下面的例子用于识别接口，详细契约见对应章节。

需要解决的问题新接口或语法怎样理解一个最小使用点
同时返回值或失败原因std::expectedstd::expected<int, ParseError> 表示整数结果或解析错误；两者不会被同一个 0 混淆
输出整条格式化消息std::print、std::printlnstd::println("value={}", 42) 输出 value=42 并换行
用多维下标访问既有存储std::mdspan一个二维视图可用 view[i, j] 访问元素；视图自身通常不拥有底层数据
用排序的连续存储保存键或键值std::flat_set、std::flat_map集合保存唯一键，映射保存键值；按键查找与插入搬移是不同成本
逐项产生结果并在遍历时恢复std::generator协程 co_yield value 暂停并提供当前值，调用者继续迭代时再恢复；寿命和分配仍要检查
收集当前位置的调用栈std::stacktracestd::stacktrace::current() 得到栈帧序列，名称和可用支持依实现
把惰性范围变成拥有结果的容器std::ranges::to将筛选后的元素收集到 std::vector，之后不再借用原范围来计算结果

语言层也有相应扩展。if consteval 根据当前是否处于常量求值选择分支；静态 operator()、operator[] 用于不依赖对象状态的调用或下标接口；显式对象参数把成员函数的对象作为可声明参数处理。模块属于 C++20 的组织机制，不能全部打包称为 C++23 新特性。

[[assume(condition)]] 向优化器承诺条件恒真，违反承诺可能产生未定义行为；它不执行输入校验。例如保证 size > 0 的内部算法才可能把这个条件作为假设，接收外部输入时仍应实际检查。先掌握契约、错误与寿命，再决定是否需要这类优化接口。

实践方法：运行、回查与独立作答

先预测程序的行为，再用本机编译器运行并比较输出。局部代码片段用于解释机制，需要结合所在类、类型定义和头文件阅读。完整程序给出预期输出，可据此检查自己的理解。

C++20/23 示例需要同时确认编译器和标准库支持，不能只看语言版本选项。

阅读性能相关示例时也要区分“写了什么”与“得到什么”：std::move 只是把对象转换成可被移动的右值，本身不移动任何数据，也不保证更快。是否更快取决于接收方调用的移动操作；是否有必要，应以实际测量为准。

编译器支持

编译器支持某个语言版本，不代表搭配的标准库实现了该版本全部组件，也不代表项目构建已启用它。确认一个接口时，按三步检查：

检查层次需要确认的内容失败时先查什么
语言模式命令使用所需的 -std=c++20、-std=c++23 或相应编译器选项实际执行的编译命令和编译器路径
语言实现编译器识别对应语法、规则和必要缺陷修正官方特性支持表与最小语法示例
库实现头文件、库接口和链接组件都可用标准库版本、相关特性测试宏和实际调用

例如能编译 C++23 显式对象参数，不足以证明 <print> 可用；能包含 <expected>，也应继续编译实际的成功与错误分支。保留工具版本和完整命令，比把一个大版本号当作“全部支持”更能复现结果。

读完和掌握分别记录

“已读”记录一次阅读，“掌握”记录能否独立解释与应用，两者分别设置。读完后只能回答一道题，可以标为已读，同时保持部分掌握；自测不会替你自动改成已掌握。

练习默认展开，先写下或口述答案，再展开参考答案并自评。不会的内容可留下问题或批注，回到对应章节；这些记录集中在“我的学习”。

用最小行为与诊断形成反馈

每次练习控制为一个接口或一条状态变化：先写正常输入，再写一个边界或失败输入，解释两种结果。阅读 fmt 的格式化实现、spdlog 的日志接口、Catch2 的测试结构时，先确定问题和版本，再观察它们如何保存状态、传递错误和管理资源。

clang-tidy、cppcheck 等静态分析工具能发现部分危险用法；运行检查和行为测试补充不同证据。出现诊断时，回到具体类型和寿命解释原因，再决定修复，不能把所有警告压掉当作完成。

构建、测试与性能分析各负责什么

基础程序能运行以后，工程知识各负责一个问题：设计模式帮助组织可变化的行为；CMake 等构建工具声明源文件、依赖和编译选项；性能分析判断时间和内存花在哪里；单元测试保存可重复的行为约束。

先完成日志统计练习（后续专题，未完成），再为自己的项目补构建与测试入口。每项工具都应服务一个已说清的问题，而不是作为额外术语列进阅读清单。

小结：沿对象、数据和责任推进

基础主线围绕三个问题展开：操作的是原对象还是副本，数据怎样进入并经过处理，资源最终由谁释放。类型与标准库阶段先让小程序可靠地读写数据，对象与资源阶段再把合法状态、复制、转交和构建边界说清。

每次阅读都留下一个可检验的结果：预测输出、修改一个输入，再解释差异。标准年份用于核对接口条件，选读目录用于回查；它们不代替实际操作，也不把已读自动变成掌握。
