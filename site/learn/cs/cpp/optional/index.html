std::optional 与类型安全

把“可能没有结果”写进返回类型，避免含糊的哨兵值和未检查的访问。

课程C++类型安全optionalC++23

建议先读类模板与函数模板流与可靠输入

本文完整程序使用 C++23 模式；可保存为代码块标题中的文件，运行 clang++ -std=c++23 -Wall -Wextra 文件.cpp -o demo，再执行 ./demo。版本标签说明特性何时引入。

用可选值表达缺失

读完本篇，你应能分别处理有值和无值的返回结果，并说明展示用默认值为什么不等于缺失状态。

用 -1 表示“没找到”只在 -1 不可能是合法结果时才可靠。一旦业务允许负数，就无法区分成功与失败。std::optional<T>（C++17）表达“有一个 T”或“没有值”，让调用者在类型上看到缺失的可能性。

它不是可空指针，也不是自动在堆上分配一个 T；它管理可选值的生命周期。没有值时返回 std::nullopt。

可选值与返回类型

当函数可能没有结果时，可选值把缺失情况放进类型。调用者在访问内容前必须检查是否有值；若需要解释失败原因，则考虑显式错误类型。

std::optional

std::optional 定义在 <optional>。std::optional<int> value; 创建无值状态，value = 3 建立整数值，value.reset() 再回到无值状态。缺失状态由类型保存，不占用某个普通整数取值。

检查状态后读取结果

last_value 接收一组整数，非空时返回最后一项，空时返回 std::nullopt。先预测两次调用的状态，再看读取方式：if (found) 检查有值，*found 读取该值，value_or(-1) 在缺失时只为本次展示选择默认值。

optional 只表达缺失，不携带失败原因。optional 自 C++17 引入；完整程序统一用 C++23 模式运行，组合接口另标 C++23 引入。

让不合法状态更难表达

类型安全并不是用一个库组件就完成了。问你的接口：调用者能不能忘记检查？缺失与错误是否被混为一谈？const、引用、智能指针、optional 各自表达不同约束。

选读：组合可空计算与可选借用

选读：C++23组合可空计算

基础主线到“检查状态并展示结果”已经闭合。需要连续处理多个可能缺失的步骤时，再读以下组合接口。

多步计算中，前一步无值时通常应跳过依赖它的后一步。可空值的组合操作（也称单子操作）把这种状态传递写成接口：and_then 接收返回 optional 的函数并展平一层；transform 映射已有值；or_else 在无值时提供另一个 optional。回调没有满足对应返回要求时不能靠语法“管道看起来合理”判断正确。

and_then、transform 与 or_else 自 C++23 引入；回调只有在对应状态下才执行。

选读：可选借用仍要检查寿命

在本文的 C++23 基线中，optional<T&> 不可用。若只需可选借用，可以用 std::reference_wrapper<T> 保存引用包装；该类型定义在 <functional>。例如 int n = 3; std::optional<std::reference_wrapper<int>> borrowed = std::ref(n); 有值时借用 n，读取 borrowed->get() 得到 int&，n 的寿命仍须覆盖这次访问。vector::back() 本身不返回 optional，空容器访问仍违反其前置条件；本篇封装是在接口层新增缺失状态。

小结：缺失状态与普通值分开保存

optional 把“有值或无值”写进返回类型，不占用 −1 等正常数值。有值时先核对需要读取什么，无值时选择明确分支；展示用默认值不改变原来的缺失状态，有值的 false 也不等于无值。

组合计算按状态决定是否执行回调，不能只看管道写法。若调用者还需要知道失败原因，就用能表达该原因的结果接口或项目约定的异常；可选借用依然不能延长被借用对象的寿命。
