用可替代关系决定继承

一个派生对象能当基类使用，还需要保持基类对行为的承诺。共享实现只是实现需求，先把它与公开接口的可替代关系区分。

public 继承需要可替代关系

把共同能力放在基类，派生类扩展行为。公开继承（public）允许派生对象在需要基类的地方使用，语义上要保持基类契约；保护继承与私有继承（protected、private）限制这种外部转换，更接近实现复用。只为共享一段代码而制造层级，通常不如组合。

选读继承：接口、动态调用与类型检查

继承是表达 is-a、接口复用和动态多态的工具，不是代码复用的默认答案。先理解 类、构造与值语义 和 六个特殊成员函数：生成规则与资源语义。

通过基类接口选择动态行为

基类指针或引用保存对象身份，虚函数根据实际对象选择实现。接口同时要规定销毁方式，不能只设计调用而遗漏生命周期。

多态对象的生命周期也属于接口

继承与访问控制

  • 公开继承：表达“派生类是一种基类”，调用者可以通过公开的基类接口使用它。
  • 保护继承与私有继承：限制外部的基类转换，更像实现复用。
  • override 应总是写，避免签名不匹配。
  • final 可阻止继续继承或重写。

这个面积接口是另一种形状设计，使用 area() 返回数值；上面的完整程序使用 label() 返回名称，两者无需放进同一个源文件。

虚函数

  • 动态派发发生在通过基类指针或引用调用虚函数时。
  • 构造和析构期间的虚调用不会派发到更派生类。
  • 多态基类析构函数应为 virtual。

提示 通过基类指针删除派生对象时，如果基类析构函数不是 virtual，行为未定义。

先核对保存下来的是什么对象，再讨论虚调用；“使用基类接口”本身不能区分借用和按值复制。

Base b = derived; 只初始化基类子对象对应的值；没有地方保存派生数据，这叫对象切片。常见实现让对象保存指向虚函数表的指针（vptr），由表（vtable）记录实际函数入口。它有助于理解动态派发，但具体位置、对象大小和调用开销不是标准保证。

例如 std::vector<Base> 按值保存基类，放入 Derived 会丢掉派生部分；std::vector<std::unique_ptr<Base>> 保留实际派生对象的所有权，再通过基类接口调用。这两个容器表达的对象关系不同，不能只把“多态”当成一种函数语法。

构造和析构期间的虚调用遵循当前构造/析构层次，不会调用还没建立或已经结束的更派生实现。普通成员函数代码也不是每个对象各存一份；this 让同一份函数逻辑访问不同对象。

组合与选读：类型检查、复杂层级

已有虚接口能完成的行为，通常无需再逐个识别具体类型。只有边界需要动态类型检查时才使用 RTTI；实现复用则可以优先考虑成员组合。

选读：需要类型探测时再使用 RTTI

先看最小入口：基类指针或引用若已能通过虚函数得到各派生类的行为（例如用 std::unique_ptr<Shape> 保存不同形状，再调用 label()），就由虚函数分派，不需要判断具体类型。下面的 RTTI 只用于虚接口之外、必须访问某个派生类专有接口的情况。

运行时类型信息（RTTI）用于根据实际对象检查类型。对多态基类指针，dynamic_cast<Derived*>(pointer) 检查它是否确实指向所需派生对象，失败返回 nullptr；引用形式失败抛 std::bad_cast。typeid 作用于多态对象表达式时可以观察动态类型，普通非多态表达式则不因此变成动态类型查询。

类型检查适合必须访问特定扩展接口的边界。普通业务分派已经能通过虚函数表达时，就不必在每个调用点重复判别类型。

基础练习先沿 Shape::label() 增加第三种形状，保持循环不变。多重继承、协变返回与继承构造函数属于下面的选读扩展，不是完成这个练习的前提。

“汽车有引擎”适合成员组合，“圆是一种形状”才是继承候选。封闭的有限类型集合也可用 variant 与 visit（后续专题，未完成）。

运行时类型识别（RTTI）

  • dynamic_cast：安全下行转换，失败时指针返回 nullptr，引用抛 std::bad_cast。
  • typeid：多态对象表达式对应动态类型，其他情形按表达式的静态类型规则判断。

运行时类型信息（RTTI）适合边界检查、插件系统、调试工具；业务分派更常见的选择是虚函数、std::variant 或 visitor。

选读：多重继承与接口扩展

多重继承让一个类同时实现多个基类接口；若两条路径都从同一个数据基类继承，就可能出现两个共同基类子对象。虚继承让这些路径共享该子对象，但共享基类由最派生类负责初始化，不能由此消除所有布局和构造复杂性。

协变返回只允许规定形式的类指针或引用，不是任意返回类型转换。例如基类返回自身引用，派生实现可以返回派生引用：

继承构造函数用 using Base::Base 引入可用的基类构造形式。例如基类接受一个编号，派生类可以复用该构造形式；派生类新增成员仍需要自己的初始化方式。

C++23 的显式对象参数把成员函数收到的对象写成显式参数，用于统一部分成员接口；它不等于虚函数的动态派发，见显式对象参数（后续专题，未完成）。

小结：保留对象，才能选择它的动态行为

公开继承先回答能否保持基类契约，再由虚函数选择实际对象的行为。基类引用可以借用完整派生对象；按值构造基类会产生另一个基类值，虚函数不能补回被切掉的派生部分。

调用和销毁都属于接口。用基类指针拥有派生对象时，要安排正确的虚析构链；只需共享实现时优先考虑组合。RTTI 用于确需探测类型的边界，不必取代已经清楚的虚接口。
