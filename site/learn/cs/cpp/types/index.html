类型系统、声明与类型转换

从变量声明开始，理解类型、结构体、类型推导和值类别，再判断隐式与显式转换的条件。

一、先看懂一条变量声明

读完本节，你应能从 int score = 8; 找出名字、类型和初始值，并预测这个变量能做什么。可以把类型想成一件工具的接口说明：它告诉编译器哪些操作有意义，但不替你检查所有业务规则。

基本类型决定常见运算

bool 表示真或假，int 表示整数，double 表示带小数的数，char 表示字符。类型会影响运算结果：整数除法会丢掉小数部分，所以 3 / 2 是 1；写成 3.0 / 2，结果是 1.5。这像厨房里选了不同量具：刻度和规则不同，得到的结果也不同。

auto（C++11）让编译器从初始值推导类型。它只省去重复写类型，并不会让变量运行时随意变成别的类型。字符串字面量例如 "hello" 在这里推导成指针；需要拥有并修改文本时，通常使用 std::string。

编译器在运行前检查表达式是否符合类型规则，这叫静态类型检查。例如 std::string text = "hello"; text - 1; 会被拒绝，因为字符串没有减法操作；但检查通过也不能证明用户输入有效或数组下标没有越界。

声明告诉编译器名字代表什么

声明像目录条目：先告诉编译器 half 是怎样调用的；定义则提供可执行的函数体。下面第一行是声明，第二行是定义，也同时是一条声明。

跨文件时，声明和定义还要由链接过程配对，见编译与链接。类定义描述一种对象的组成；只有定义完整后，才能创建该类对象。

名字、对象与引用不是一回事

对象是在程序中保存状态并有寿命的实体；变量名是访问它的名字。引用（reference）是已有对象的另一个入口，不会另外复制一份对象。比如 int& alias = score; 让 alias 和 score 指向同一个整数，改其中一个名字看到的值也会变。

函数类型描述参数和返回值。struct Student; 只宣布有 Student 这个类型，还没说明它包含什么；此时可以声明 Student* 指针，但不能创建 Student 对象，因为编译器还不知道对象大小。

先分清限制访问和延长寿命

const int limit = 10; 表示不能通过 limit 修改这个整数。函数里的 static int calls = 0; 则让该局部变量在多次函数调用之间保留值。这两个关键字回答不同问题：const 管访问，static 在这里影响对象寿命。

例如每次调用函数都执行 ++calls，这个计数会延续上次的值；普通局部变量若每次初始化为 0，就不会保留这个累计结果。

控制流关键字负责选择下一步

if 和 switch 选择分支，循环重复执行，break、continue、return 改变接下来运行的位置。try、catch、throw 表达异常传播；noexcept 是函数不抛异常的承诺，详见错误处理（后续专题，未完成）。namespace 管理名字，下一节会用它区分同名实体。

二、用合适的类型表达一条记录

一条订单有编号、金额和状态。若所有内容都塞进几个整数，代码虽能编译，却很容易把编号当金额、把状态当数量。给数据取清楚的名字、组合相关字段，能让错误更早暴露。

命名空间像给名字加上所属目录

不同库可能都有 print 函数。命名空间给名字一个范围，first::print 和 second::print 就能清楚地区分；:: 读作“属于”。标准库的名字也放在 std 中，因此常写 std::string、std::cout。

函数重载让同一个动作接收不同输入

函数重载（overload）是多个同名函数使用不同参数类型或数量。像同一个“计算一半”的按钮，整数输入走整数版本，带小数的输入走浮点版本。不能只靠返回类型区分重载。

结构体让相关字段有名字

结构体（struct）把一组相关字段组合成新类型。字段名像表格列名，能直接说清值的含义；大括号里的初值按字段声明顺序排列。

std::pair（定义在 <utility>）把两个值按 first、second 保存，适合含义简单的一对数据。若读者必须记住“first 是名字、second 是年级”，具名结构体更清楚。std::tuple 可以装更多元素，但仍按位置访问。

枚举表达有限状态，别名提供短名字

using 类型别名（C++11）给已有类型取一个便于阅读的名字，例如 using UserId = int;；它不会创造一种编译器能与 int 区分的新类型。

当状态只有几种固定选项时，用枚举比散落的数字更容易读。enum class（C++11）声明一个独立的枚举类型，枚举项需要带上类型名访问，也不会悄悄当成整数使用。

这像给交通灯规定合法标签：代码读到 shipped 比读到数字 2 更容易理解，也不容易把状态误当数量。这里不需要记住每个状态对应哪个整数，只需用它的名字。

选读：不同数据共用存储时

union 让多个成员共用一段存储，使用者必须跟踪当前哪个成员有效。日常业务中的“整数或字符串”通常使用 std::variant 更稳妥，见标准库工具类型（后续专题，未完成）。

三、让 auto 帮忙写类型，再核对结果

auto 是根据初始值填写类型的简写，像表单里从已填信息自动补全字段。关键决定仍由你做：要一份独立副本，还是借用原对象？

先决定复制，还是引用原对象

按值声明创建新对象；引用则访问已有对象。复制一个含指针或共享资源的复杂对象时，复制的具体含义由该类型定义，未必会复制它指向的资源。

按值推导会去掉对象本身的 const

这里 auto 按值创建新对象，因此 a 可以修改，不影响 x。引用没有创建副本，所以保留原对象的只读限制。对指针而言，const int* 中的 const 限制的是所指整数，复制指针后这个限制仍在。

选读：decltype 用来询问表达式的类型

decltype(name) 对普通变量名取得变量声明的类型。需要理解的细节是：普通变量名有一条特别规则，而加括号后按表达式处理；表达式 x 表示正在访问原对象，因此 decltype((x)) 是引用类型。

先掌握 auto 的副本与引用差异即可。decltype(auto) 和复杂返回类型会沿用同一规则，可能不小心返回局部变量的引用；看到这种写法时，要确认局部对象是否仍然存在。

遍历容器时用 auto 减少重复

容器迭代器类型往往很长，初始值已经能表达意图时，用 auto 可以让代码更清爽。只读借用元素可写 const auto&，要修改元素则写 auto&。

若类型是接口的重要组成部分，直接写出类型也有好处：读者不必跳回初始值猜它是什么。

五、转换之前先检查会不会丢信息

转换有时自动发生，有时要由程序员明确写出。像把食材倒进不同刻度的量杯：操作可能允许，但小数、范围或原有只读限制可能无法保留。先用小数字手算，再决定是否值得转换。

隐式转换会在赋值和传参时发生

double x = 3; 自动把整数表示为 3.0。int y = 3.9; 会向零截断，得到 3；若使用 int y{3.9};，大括号初始化会拒绝丢失小数的窄化转换。读代码时可以先手算：目标类型装得下吗？小数部分是否会消失？

把米数包装成 Meter 类型，可以避免把普通数字意外当成长度。下面 Meter(double value) 是构造函数，负责创建对象；冒号后的 value(value) 把传入的数放进同名成员。explicit 要求调用者明确表达这次创建。

explicit 的意思是“这种构造需要明确选择”。这里它防止函数参数或赋值时意外创建 Meter；直接写 Meter{2.5} 则清楚表达了意图。例如一个函数需要 Meter 参数，就应传入 Meter{2.5}，而不是让裸数字 2.5 悄悄转换。

需要转换时选择说明意图的写法

static_cast<int>(3.9) 明确要求得到整数 3，但代码写明了意图不等于业务上合理。浮点值超出目标整数可表示范围时，转换不能安全完成。

C++ 有几种具名转换，各自用途不同：static_cast 用于常见数值转换等；dynamic_cast 在符合条件的多态继承关系中做运行时检查；const_cast 调整访问限定；reinterpret_cast 用于少数低层表示转换。它们都不会自动证明结果适合业务，也不能绕过对象寿命和类型访问规则。

普通业务代码很少需要 reinterpret_cast；它不会让不符合规则的跨类型读取变安全。C 风格转换也容易隐藏实际采用了哪种规则，因此优先使用能表达意图的具名转换。

小结：用三个问题读懂陌生声明

遇到不熟悉的 C++ 声明，可以按顺序检查：这会创建新对象还是借用旧对象？表达式代表哪个对象或临时结果？转换会不会丢掉范围、小数或只读保证？

先预测最常见的三种结果

这三个判断足以解决许多日常阅读问题：auto 按值时复制成普通 int；std::move 需要后续操作才可能触发移动；转换的结果要结合目标类型检查。

从选择类型走向清楚的接口

数量用合适的数值类型，有限状态用枚举，相关字段用结构体；只读借用写在 const T& 参数里。类型能帮编译器检查许多误用，但范围、寿命与业务条件仍要由程序逻辑保证。

选读：遇到这些术语时再查

进阶阅读时可能遇到 const T&& 和“右值物化”。它们描述更细的对象传递规则：const T&& 通常无法绑定到接受 T&& 的移动构造，因为去掉 const 会违背只读保证；右值物化则是在语言需要对象身份时，为纯右值创建临时对象。普通变量声明和函数调用不要求先掌握这些机制，遇到移动构造或模板推导专题时再深入即可。

volatile 用于保留某些可观察访问，常见于硬件接口，不能代替线程同步；它与 const 合称 cv 限定符。thread_local 为每个线程保存一份对象，extern 常用于声明在别处定义的变量。mutable 可让类中指定成员（例如缓存）在 const 对象中更新，见const 正确性。这些工具解决的是特定场景，普通声明不需要把它们全部用上。
