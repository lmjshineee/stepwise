构建阶段与声明边界

预处理展开包含和宏；编译把各翻译单元转成目标文件；链接解析目标文件间的符号。头文件不是自动编译的一份实现，包含它的每个 .cpp 都会看到其中内容。每个源文件连同它包含的头文件经预处理后形成一个翻译单元；目标文件保存已编译代码以及待链接的符号。

声明让编译器知道调用形式，函数定义提供实现，目标文件中的相应符号让链接器连接调用与实现。把普通非 inline 函数定义放在多个源文件包含的头文件里，常造成重复定义；只有声明、缺少实现或没有链接对应目标文件，则常出现未定义符号。单一定义规则（ODR）约束定义出现的位置和数量：同一翻译单元不能重复定义；这里的普通非 inline 函数在程序中只应提供一份定义。类、模板和 inline 等允许满足条件的跨翻译单元定义，但要求定义及名字查找等保持规定的一致性；不能仅用“链接器没报错”判断合法。包含保护只能阻止同一翻译单元内的重复展开，不能阻止两个 .cpp 各包含一份普通函数定义。

模板通常需要在实例化处看到定义，常放在头文件；显式实例化是另一种受控方案。

编译模型

  • declaration 声明：告诉编译器名字、类型和接口。
  • definition 定义：提供实体本身，分配存储或给出函数体。
  • ODR：同一实体在整个程序中通常只能有一个定义，模板和 inline 是受规则约束的例外。
  • translation unit：一个源文件包含头文件预处理后的结果。
  • linkage：名字是否能跨翻译单元被看见，常见有 external、internal、no linkage。

提示

头文件心法 头文件放声明、模板定义、inline 函数、constexpr 函数和类型定义；源文件放非模板函数定义和私有实现细节。

链接器、标准库与编译器是不同层次。切换 -std=c++23 只选择语言模式，不能保证所有新库组件可用。Modules（后续专题，未完成） 还要处理模块接口的编译依赖和产物。

目标级 cxx_std_23 请求至少 C++23 的语言能力；它不代表标准库全部新组件都已实现。完整多文件例子使用 iostream，先验证源文件与链接关系；用到 println 或其他新库接口时，还应编译实际调用。

若项目已有 Makefile，先读它的目标与源文件列表。构建工具负责决定要执行哪些命令，不能因为换成 CMake 就忽略第一条编译或链接错误。

错误先检查
找不到头文件包含路径、大小写、依赖是否存在
不匹配的函数调用参数、const、约束、可见声明
undefined symbol是否提供定义、是否链接实现、签名是否一致
duplicate symbol是否把普通定义重复放进多个翻译单元
运行结果没变编译是否成功、输出路径与实际运行文件是否相同

小结：声明、实现、目标文件和运行逐层核对

头文件声明让调用形式可检查，目标文件中的定义让链接能够完成。main.o 能生成，不代表单独链接它就能找到 twice；包含保护也不能消除不同翻译单元里的重复普通定义。

CMake 配置描述构建规则，实际构建执行编译和链接，运行再验证行为。按失败阶段找第一条相关诊断，确认修改进入了正确路径下的新程序；语言模式、标准库支持与构建输入各要分别核对。
