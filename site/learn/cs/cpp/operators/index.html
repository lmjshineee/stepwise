运算符语法与成员调用

运算符重载至少涉及类或枚举类型，不会改变优先级、结合性或操作数数量，也不能发明新符号。.、::、?: 等不能重载。读者期待 + 返回相加结果、+= 改变左操作数、<< 写入给定流；把运算符变成隐蔽的网络请求会增加理解成本。

成员二元运算中左操作数是调用对象。希望两侧都允许相同的隐式转换时，非成员函数通常更对称。非成员只有需要访问私有状态时才需要 friend；使用公共接口的非成员并不必然是友元。

运算符重载：设计符合直觉的接口

把 20 分钟与 15 分钟相加时，你期待结果为 35 分钟，并保留两个原始时长。这个约定比“类能用加号”更重要：+ 产生新值，+= 修改左边对象。下面沿同一份 Minutes 类观察两者。

先约定值的含义，再选择成员或非成员

成员二元运算符接收右边参数，左边由当前对象提供，例如 a.operator+=(b) 对应 a += b。非成员则显式接收两边。

非成员函数若只通过公开接口工作，就不必是 friend。友元授权只在需要读取私有数据时使用；它不会让该函数变成类成员。

非成员、友元与流输出

operator<< 的左边是输出流，所以通常写成非成员；返回收到的同一个 std::ostream&，下一次 << 就能继续写到同一流。它不应偷偷改写右边的对象或强制输出到另一个流。

对需要对称表达的运算，可以让非成员转调成员。例如若类已提供 Time::operator*(double) const，非成员 Time operator*(double factor, const Time& time) { return time * factor; } 就让 1.5 * time 复用与 time * 1.5 相同的检查。时间若保存整数分钟，乘法还必须说明小数分钟如何取舍、是否允许负值和溢出；单纯重载语法不会替你决定业务规则。

三向比较与相等关系

C++20 默认化 <=> 按成员顺序组合比较，并在满足规则时隐式声明默认的 ==。手写 <=> 并不自动替你手写 ==。浮点值可能产生 unordered，不能把所有比较都当作总序。

如果按年龄比较 Person，却让相等比较包含姓名，排序等价和相等语义可能不同；必须明确业务需要。用于 map/set 的比较还必须满足严格弱序。

friend 授予特定访问权限，不是成员身份，也不自动继承、传递或对称。上面的 Time 乘法片段还需要补齐输入范围和小数取舍规则，才能作为具体业务接口使用；运算符语法本身没有提供这些规则。

示例采用 <compare> 中配套的三向比较规则（C++20）。默认化比较按成员声明顺序比较；Minutes 只有一个整数成员，因而相等和大小都由它决定。若加入姓名或单位，需重新判断默认比较是否仍符合业务含义。

三向比较运算符 (<=>)

默认化的三向比较与手写实现遵循不同规则。手写 operator<=> 不会自动提供完整的相等比较；涉及浮点数时，还要考虑无序比较结果。

小结：符号要保留读者熟悉的含义

先约定对象的业务含义，再设计运算符。值加法通过副本保留原值，复合赋值修改当前对象，流输出返回原流以便继续写入；成员、非成员和友元分别解决调用形式与访问权限。

比较也要服从同一套业务语义。默认化三向比较与手写实现的相等规则不同，增加成员后要重新检查排序与相等是否仍合理；重载不会自动处理溢出、单位或小数取舍。
