第一个 C++ 程序与编译流程

运行第一段 C++23 模式程序，区分编译、链接与执行，并确认每次修改确实进入新程序。

课程C++CS106L编译工程实践C++23
开始自测
本篇的学习目标编译并运行一个 C++23 模式程序，读懂编译命令与诊断，再通过修改输入核对输出。先建立可以反复验证的小环境。
建议先读CS106L

本文完整程序使用 C++23 模式；可保存为代码块标题中的文件，运行 clang++ -std=c++23 -Wall -Wextra 文件.cpp -o demo，再执行 ./demo。版本标签说明特性何时引入。

准备编译器与源文件

需要支持 C++23 模式的 Clang 或 GCC，以及终端和文本编辑器。在 macOS 中可先运行 clang++ --version；命令不存在时安装 Xcode Command Line Tools。在 Linux 中确认 g++ --version。下面的命令使用 Clang，GCC 用户把 clang++ 换成 g++ 即可。

-std=c++23 明确本课程的编译模式，-Wall -Wextra -pedantic 打开常见诊断。警告不是所有错误的检测器，但能帮助你发现隐式转换、未使用变量等问题。

预测、编译并运行第一个程序

保存为 main.cpp。注意头文件拼写是 <iostream>；std:: 指定名称来自标准库命名空间。

预期输出：

student.exercises 用点号取出 student 的 exercises 成员，值是整数 3，所以 total 是 3 + 2。

std:: 明确名称来自标准库，例如 std::cout、std::string。在头文件里写 using namespace std; 会让每个包含它的文件都把整个 std 引入当前作用域，更容易与自己或其他库的同名名称冲突；头文件会影响所有使用者，所以应保持显式写 std::。

auto（C++11）让编译器从初始化表达式推导类型。这里 total 是 int，不是随时改变类型的动态变量。Student 把姓名与练习数组合成一个有意义的类型；类类型、模板类型与内建类型都参与静态类型检查。

区分构建失败与运行错误

现象可能的位置检查方法
头文件找不到、缺分号、类型不匹配编译阶段从第一条诊断开始，核对文件和行号
函数有声明，却没有定义链接阶段检查定义是否存在、是否编译进目标
程序成功启动，但结果错误运行阶段缩小输入，预测状态，再打印或调试

修改代码后必须重新编译；运行旧的可执行文件不能证明新代码正确。std::endl 会输出换行并刷新流，普通逐行输出通常用 '\n' 即可。

通过一次修改核对理解

把练习数改成 8，重新编译，输出应为 Learner: 10。再故意把 exercises 写错，观察编译器的定位。最后修复它。

下一步先读 类型、struct 与 auto，解释这个 Student 为什么能同时返回姓名和练习数；再进入 引用与初始化，判断修改的是原对象还是副本。

小结：确认运行的是刚刚修改的程序

源文件保存的是程序描述，可执行文件是构建产生的另一个文件。每次修改后，先确认编译和链接成功，再运行正确路径下的新程序；看到旧输出时，先检查这条链是否接通。

读懂示例还要能解释 Student 保存了哪些字段、auto 从什么表达式推导类型。把练习数从 3 改成 8，先算出 10，再与输出比较，才完成一次能重复的验证。
