先让一个对象负责资源的获得和释放

读完本篇，你应能沿着一段程序指出：谁负责释放资源，责任何时转交，正常退出和异常时分别由谁清理。

假设函数在 new 之后还要做几项工作。只在末尾写 delete，中途新增的 return 或异常就可能跳过释放。资源获取即初始化（RAII，Resource Acquisition Is Initialization）把这项责任交给对象：获得资源后由对象管理，在对象析构时释放。资源也可以是文件或锁。

unique_ptr、shared_ptr、weak_ptr 与 make_shared 自 C++11 引入，make_unique 自 C++14 引入，都在 <memory> 中。

先只看一个所有者。std::make_unique<Resource>() 创建一个 Resource，返回负责删除它的 std::unique_ptr<Resource>。-> 访问被管理对象的成员。把下面每个完整程序分别保存为 example.cpp，用 clang++ -std=c++23 example.cpp -o example && ./example 运行。

资源获取即初始化（RAII）

RAII 管理的不只是内存，也包括文件、锁、socket、事务、临时状态。

上面的 std::lock_guard 是锁的 RAII 管理者：构造时加锁，析构时解锁。片段需要 <mutex>，mutex 是已有的互斥量。是否保护了所有共享访问，仍取决于程序的加锁范围。

先转交独占责任，再选择是否共享

智能指针：让类型表达资源所有权

智能指针是管理对象寿命的类模板，定义在 <memory> 中。unique_ptr 独占资源，shared_ptr 共享释放责任，weak_ptr 只观察共享资源。先用独占指针说明责任怎样转交，再考虑需要共享的情况。

复制 unique_ptr 会让“唯一的释放责任”变成两份，因此它禁止复制。需要交接时使用移动：std::move 在 <utility> 中，把表达式转换成可供移动操作选择的形式；实际接管资源的是目标指针的移动构造函数。

unique_ptr

std::unique_ptr<T> 表示独占所有权。

下面的接口片段假定 Widget 可以用整数 42 构造；p 与 q 的交接规则和刚才的整数例子相同。

  • 不能拷贝，只能移动。
  • 默认删除器调用 delete。
  • 可以带自定义 deleter。
  • 适合表达“我拥有这个对象，且只有我拥有”。
表达方式责任常见使用场景
unique_ptr<T>唯一所有者，可移动，不可复制一个对象负责资源寿命
shared_ptr<T>共享所有者，共享控制块多个独立持有者共同负责寿命
weak_ptr<T>观察共享对象，不增加强引用计数反向关联、缓存观察、打断所有权环
T& / T*通常表达借用，接口需说明寿命临时访问一个已有对象

优先使用值成员或独占所有权。函数只想读取一个对象时，通常传引用就够了；“需要访问”本身不是共享所有权的理由。

reset() 释放原对象并改接新指针，release() 只交出裸指针并放弃管理，不执行删除。混淆这两个名字会造成泄漏；接过 release 返回值的一方必须立即建立新的所有权安排。

不要给同一个裸指针分别创建两个独立的 shared_ptr 控制块；那不是共享同一份责任，而是两组对象分别打算删除它。优先由 make_shared 创建，再复制已有句柄。

裸指针和引用

  • T&：非空借用，生命周期由调用者保证。
  • T*：可为空借用，或 C API 交互。
  • std::span<T>（C++20）：连续区间借用，可用于连续数据借用，但仍要保证原数据存活。
  • std::string_view（C++17）：字符串借用。

裸指针可以表达非拥有关系，但不要让它悄悄承担所有权。

借用不负责释放，也不会阻止所有者销毁。即使指针或视图还留在手上，原对象已经销毁后也不能再访问它。

确需共同负责寿命时，再用共享指针

假设缓存和预览窗口各自保存一份资源句柄，关闭窗口后缓存仍要保留资源，清空缓存后窗口也可能仍在使用。两者的持有时间互不包含，可以让 shared_ptr 表达共同所有权。它们共享的控制块记录所有者数量，称为强引用计数；最后一份所有者离开时才销毁对象。

我们使用 make_shared 函数来初始化智能指针，分配内存。make_shared 是一个模板函数，函数名后跟一个尖括号给出参数类型。

复制已有的 shared_ptr 会增加该共享所有权组的强引用计数；销毁或替换一个所有者会减少旧组的计数。赋值到另一个组时，还会增加新组的计数。返回对象不一定发生复制，不能只凭语法统计计数变化。当某个控制块的强引用计数降为 0 时，被管理对象销毁；仍有 weak_ptr 时控制块本身可能继续存在。引用计数属于共享控制块，不是每个指针各自维护一份独立所有权。

让成员管理资源；pImpl 留作选读

如果类成员都能自己管理资源，类通常不需要手写析构，这称为零法则（Rule of Zero）。可复制、可移动性仍由成员决定：持有 unique_ptr 的类默认不能复制；需要独立副本时，要明确实现深复制，而不是偷偷变成共享。

make_unique 与 make_shared

  • std::make_unique<T>(args...)：简单、安全、异常安全。
  • std::make_shared<T>(args...)：对象和控制块通常一次分配，缓存友好。
  • 需要自定义 deleter、私有构造或特殊控制块时，可能不能直接用 make_shared。

选读：实现指针（pImpl）隔离接口与实现

pImpl 隔离实现细节，降低编译依赖。因为 Impl 是不完整类型，析构函数通常要在 .cpp 中定义。

impl_ 独占实际实现对象，头文件只声明 Impl 的名字。默认删除器真正删除对象时需要完整类型，因此析构函数在能看到 Impl 定义的实现文件中定义。这里显式声明了析构和移动操作；仅仅写一个析构声明也会影响隐式移动的生成。

把释放责任写进成员类型

资源管理的核心是 RAII：资源在构造时获得，在析构时释放。它建立在 六个特殊成员函数：生成规则与资源语义 和 移动语义：std::move 到底做了什么 之上。

小结：把释放责任交给会按规则析构的对象

RAII 把资源清理绑定到管理对象的寿命：正常作用域退出与异常栈展开都能触发清理，强制终止不属于同样的保证。管理者和被管理资源是不同对象，本篇独占指针的移动改变责任归属，没有复制资源。

先用值成员或独占所有权，确需共同负责寿命时才共享。weak_ptr 不增加强所有者，访问前用 lock 取得并检查临时所有者。寿命管理不等于内容同步，自动关闭也不代替仍需报告的 I/O 错误。
