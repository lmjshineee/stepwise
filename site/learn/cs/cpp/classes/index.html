让成员负责各自的资源

Notebook的vector和string已经管理自己的存储，Notebook没有手写复制、赋值或析构函数，仍能得到上面需要的独立值行为。这就是零法则（Rule of Zero）的用途：优先用能自行管理资源的成员组合类，让默认操作承担复制和清理；它不是“不能写任何构造函数”，上面的Student仍可以有检查年龄的构造函数。

是否允许复制还取决于成员支持什么：string/vector支持复制，独占智能指针通常不支持复制。先确定你的类需要独立值还是独占所有权，再到 特殊成员函数 检查完整生成规则；不必在这个年龄例子中一次手写六个操作。

把只读访问写进成员接口

size() const 承诺不通过此对象接口修改普通成员。返回元素时还需选择 const T&；仅在函数尾部写 const，不等于返回的对象自动只读。

选读：运算符接口与友元

运算符重载应当保持读者熟悉的含义。例如 operator<< 通常返回同一个 ostream& 支持链式输出。friend 是选择性授予访问权限，不是成员函数身份，也不自动对称或传递。

选读：特殊成员的生成与资源策略

操作典型签名职责
默认构造T()创建初始对象
析构~T()对象结束时清理
复制构造T(const T&)从已有对象创建独立值
复制赋值T& operator=(const T&)覆盖已有对象的值
移动构造T(T&&)从可被消耗的对象初始化
移动赋值T& operator=(T&&)向已有对象转交资源

编译器是否隐式声明这些函数、它们是否被删除，取决于你声明了哪些函数，以及成员和基类支持哪些操作。用户声明析构函数会阻止隐式移动操作的生成；包含 unique_ptr 的类也不会自动获得可行的复制操作。

优先 Rule of Zero：用 string、vector、智能指针等自己管理资源的成员，让默认操作组合出正确行为。必须直接管理裸资源时，再整体审视 Rule of Three/Five，而不是机械补齐函数。

选读：多文件类定义与继承边界

如果你需要通过基类指针多态销毁派生类对象，基类应有虚析构函数。派生类覆盖虚函数时写 override 帮编译器检查签名；把派生对象按值赋给基类对象会发生切片，派生部分不会保存在基类值中。

只有共享代码而没有可替代关系时，优先考虑组合。后续的 移动语义 会把“值怎样被复制”扩展到“资源怎样被转交”。

选读：默认构造与接口标记

  • class 默认 private，struct 默认 public；差异主要是默认访问控制。= default、= delete、noexcept 自 C++11 引入。Widget() = default 请求默认构造，explicit Widget(int) 阻止整数隐式变成 Widget，noexcept 表示异常若逃出该函数会终止程序。
  • 成员初始化优先使用 member initializer list。
  • 成员实际初始化顺序由声明顺序决定，不由初始化列表顺序决定。
  • const 成员函数限制经当前对象接口修改普通成员；mutable 成员和指针指向的其他对象仍可能变化，逻辑只读需要另行设计。

基础检查表

  • 名字是否有清晰的声明和定义边界？
  • 成员是否在构造阶段完全初始化？
  • const、noexcept、explicit 是否表达了真实意图？
  • 是否避免裸 new/delete？
  • 是否知道对象何时构造、何时析构？

小结：每条公开路径都维护同一规则

类的不变量要在成功构造后成立，也要在每次公开修改后成立。先检查请求是否合法，再改变状态，才能让失败修改保留原来的合法值；把成员设为 private 只是限制入口，真正的规则仍由接口实现。

复制构造创建新对象，复制赋值改变已有对象，二者都不等于绑定别名。优先让 vector、string 等成员管理各自资源，再按需要设计只读接口和复制策略；不要为了展示语法给每个类都手写六种操作。
