移动语义：std::move 到底做了什么

先观察引用绑定与所有权交接，再用值类别解释重载，检查移动后的对象与const来源。

建议先读类、构造与值语义

本文完整程序使用 C++23 模式；可保存为代码块标题中的文件，运行 clang++ -std=c++23 -Wall -Wextra 文件.cpp -o demo，再执行 ./demo。版本标签说明特性何时引入。

先区分引用绑定与新所有者的构造

读完本篇，你应能指出 std::move 出现后是否真的转交了资源，并分别检查来源对象和接收方的后续操作。

先沿用独占所有者。std::make_unique<int>(42) 创建整数并返回负责删除它的管理对象；auto&& candidate = std::move(owner) 则给已有的 owner 绑定一个引用，不创建新的管理对象。接着构造 next，观察责任何时交接。

std::move 定义在 <utility> 中，它允许表达式参与移动操作的选择，本身不搬运资源；具体的构造或赋值决定实际行为。各完整程序分别保存为 example.cpp，运行 clang++ -std=c++23 example.cpp -o example && ./example。

预期输出：

第一步只绑定引用，owner 仍然持有资源。第二步初始化新的 unique_ptr，移动构造才转交所有权。此后来源智能指针为空，这是该类型明确的保证。

执行到哪里管理对象之间的关系谁拥有整数
创建 owner 后只有一个管理对象owner
绑定 candidate 后candidate 引用的就是 owner，不是第二个管理对象仍是 owner
构造 next 后新建第二个管理对象，接管原来的整数next；owner 与它的别名 candidate 都看到空状态

移动没有让 owner 提前析构；局部对象仍按作用域规则结束寿命。需要分清“给对象绑定另一个名字”和“用它构造一个新对象”。

unique_ptr（C++11）可以先理解成一张唯一的删除责任单；make_unique（C++14）同时创建对象和责任单。移动后由下一张单负责，原管理者变空。这个类型只是让资源交接更容易观察，后面的 RAII 会展开文件、锁与共享责任。

右值引用和 std::move 自 C++11 引入。std::move 仍然保留来源的 const 限定，也不会缩短来源对象的寿命。

再用值类别解释重载为什么不同

同一对象可以出现在不同形式的表达式中，值类别描述的是表达式，不能只看变量的声明类型。左值（lvalue）标识一个对象或函数；将亡值（xvalue）也标识对象，但允许它参与资源复用的操作；纯右值（prvalue）用于计算值或初始化对象。右值是纯右值与将亡值的合称。

表达式类别本例里的含义
owner左值使用已有的管理对象
std::move(owner)将亡值仍指同一个对象，允许选择移动操作
candidate左值通过有名字的引用使用已有对象
42纯右值用于计算或初始化的整数值

左值引用写成 T&；右值引用写成 T&&。下面两个 category 是重载函数：编译器按实参选择能绑定的参数。int&& ref = 7 把引用绑定到临时整数，但表达式 ref 因为有名字，仍是左值。

预期输出：

这里的 rvalue 是函数输出的标签；最后一次传入的具体类别是将亡值。函数体只打印，不转交资源，因此“选中了右值引用参数”也不能单独证明发生了移动。const 左值不能赋值，所以“能放在赋值号左侧”不是左值的完整判断方法。

值类别再整理

有名字的表达式通常是左值，但左值不一定可以赋值，也不一定长期存活。移动后对象的有效状态及允许的操作，应依据具体类型的约定判断。

  • lvalue：标识对象或函数的表达式，具有身份；寿命和可修改性需另行判断。
  • prvalue：用于初始化的纯右值。
  • xvalue：资源可被“掏走”的将亡值。

std::move 只做类型转换，不执行移动；真正移动发生在移动构造或移动赋值中。

右值引用

std::string&& 可以绑定到右值。但一旦右值引用变量有了名字，它本身是 lvalue：

有名字的右值引用仍是左值表达式

移动构造函数的参数 T&& other 有名字，因此表达式 other 是左值。移动其成员时可能需要 std::move(other.member)。另外 std::move 不会去掉 const；从 const 对象“移动”，常常仍然调用复制操作。

返回局部变量时通常写 return result;，让复制消除与隐式移动发挥作用。不要机械写 return std::move(result);，它可能阻止命名返回值优化。

移动后的源对象与资源所有权

对于标准库中通常的移动操作，来源对象处于“有效但未指定”的状态，除非该类型规定了更具体的后置条件。它可以析构、赋值，也能调用满足前置条件的操作；不能假设它保留原内容，或一律为空。

source 没有被销毁。这里先清空再追加，让后续状态明确，不依赖移动后的具体内容。读取 front() 要求非空；直接对一个状态不明确的容器调用它，是需要排查的地方。

移动后的源对象：有效但状态可能未指定

被移动后的对象仍然有效，但值通常未指定。可以析构、重新赋值，除非类型文档给出更多保证。

提示

不要假设 std::string 被移动后一定为空。常见实现可能如此，但标准不要求。

与智能指针的关系

  • std::unique_ptr<T> 只能移动，不能拷贝。
  • std::shared_ptr<T> 移动时转移控制块引用，拷贝时增加引用计数。
  • 见 RAII 与智能指针：把释放责任交给对象。

选读：把同一规则用于vector移动

复制一个 vector 得到独立元素；移动构造新 vector 可以转交来源的存储。std::move 定义在 <utility>，它本身只改变表达式的值类别。

这份接口返回引用，不创建新对象，也不把来源变成“赋值后销毁的临时变量”。具名对象 s 是左值表达式；std::move(s) 是仍标识同一对象的将亡值表达式。T& 可以绑定合适左值，T&& 可以绑定合适右值，声明引用时仍必须初始化。

右值引用与移动语义

MyString 的片段仅用于说明移动操作，完整的资源类还需要构造、复制策略和析构函数。是否声明 noexcept 会影响容器的选择，但不能据此断言容器一定不会移动元素。

最佳实践：

  • 移动确实不抛时才标记 noexcept；可用复制时容器可能选复制，不可复制时仍可能移动
  • 使用 std::move 将左值转为右值引用
  • 使用 std::forward 进行完美转发

选读：完美转发与复制省略的条件

  • T&& 在类型推导语境中是 forwarding reference。
  • std::forward<T> 保留传入参数的值类别。
  • 转发引用是参与推导的、未加 const 的模板类型参数 T 的右值引用；不是所有 T&& 都是转发引用。此模式按 T 恢复传入类别，主动消耗已知对象通常用 std::move。

逐次检查资源转移

  1. 接收方究竟调用了哪个操作？
  2. 来源对象的类型保证什么后置条件？
  3. 后续代码还会不会依赖原有内容？
  4. 这次移动是否真的解决了已测量的成本？

检查第 1 项时要留意 const：std::move 只是把表达式转换成右值引用，不改变 const 属性。对 const T 对象调用 std::move 得到 const T&&，通常的移动构造函数 T(T&&) 不能接收它；如果存在 T(const T&)，重载决议可能选中复制，代码看起来在“移动”，实际是复制。

这组问题与 RAII 的所有权关系一起使用，才能理解资源最终由谁释放。

用一对重载观察这个区别。Trace(const Trace&) 是复制构造，Trace(Trace&&) 是移动构造；本例不管理资源，只打印被选择的操作。

预期输出：

第一次能把来源绑定到 Trace&&。第二次的来源仍带 const，不能绑定到这个移动构造的参数，但可以绑定到复制构造的 const Trace&。因此要检查类型提供的重载，不能只统计代码里出现了几次 std::move。

移动时仍要核对接收方与来源

把 std::move 用到接口前，先检查目标类型是否有可用移动操作、来源是否为 const，以及移动后代码是否继续依赖原内容。智能指针、字符串和自定义资源类的后置条件可能不同，不能统一假设移动后为空。

选读：按值接收再移动到成员

按值接收再移动适合需要保存值的构造函数：左值通常先复制到参数，再移动到成员；右值可能先移动或直接构造参数，再移动到成员。不要把它概括成所有场景只发生一次操作。

小结：转换、接收操作与来源状态分开看

std::move 只改变表达式参与重载选择的方式；绑定引用没有创建新所有者，真正的构造或赋值才可能执行移动。具名右值引用仍是左值表达式，const 限定也不会被 std::move 去掉。

发生移动后，再按具体类型检查来源的后置条件。本篇 unique_ptr 移动构造后的来源明确变空，其他类型不能一概套用；来源对象仍要按作用域析构。先建立允许继续使用的状态，再检查这次操作是否解决了实际成本。
