用 C++ 开始写题：从函数接口到常用容器

写通两数之和、排序去重与标准输入输出，建立可以提交和本地检查的 C++ 解题习惯。

教程C++C++23LeetCode算法快速上手
开始自测
建议先读引用与初始化容器

会写循环，却在写题时被 vector、函数签名和输入格式卡住，通常不是算法本身太难，而是还没把“题目交给你什么”与“C++ 怎么表达”接起来。这篇先写通一道函数型题，再准备一组够用的容器操作，最后迁移到标准输入输出题。

需要已经能读懂变量、if、for 和普通函数；还不熟悉时，可以先看第一个程序、引用与初始化和容器。本篇不要求先学完模板、继承或手动内存管理。

本地示例按 C++23 编译。2026-10-17 核对 LeetCode 官方环境页时，其 C++ 环境标为 Clang 19、C++23；其他平台仍要查看各自选项。本文使用的 std::ranges::sort 和 std::ranges::unique 从 C++20 引入；结构化绑定、if 初始化语句从 C++17 引入。

先判断：提交函数，还是提交整个程序

LeetCode 常见模板把入口交给平台：它创建参数、调用 Solution 的指定方法、比较返回值。你的任务是保留题目给定的类名、方法名和参数形式，实现方法体；不要额外添加读取终端的 main，也不要把本应返回的数组改成打印几行字。

标准输入输出型题则由你提供完整程序：main 读取题面约定的数据，调用算法，再按要求输出。把前一种解法原样交给后一种评测器，会因为缺少入口而失败；把本地测试入口一起贴进函数型题，也可能产生重复定义。

先确认的事函数型题标准输入输出型题
谁创建输入平台提供参数main 解析输入
结果交到哪里方法返回值或题目指定的修改标准输出
本地怎样测自写 main 调方法，提交时移除它用样例输入运行完整程序
调试信息不要依赖打印作为答案不要混进规定输出；本地诊断可用标准错误

用一道“两数之和”把接口和容器接起来

任务是返回两个不同位置的下标，使它们的值相加等于目标。官方题目保证恰有一个解，数组长度不超过一万；例如 [2,7,11,15]、目标 9，返回 [0,1]。注意，返回的是位置，不是数值 2 和 7。

先写出正在维护的信息

如果每个位置都向后再找一次，需要两层循环，最坏做二次方级别的比较。另一种办法是从左到右扫描，把“之前见过的数值及其下标”留在哈希表中。

来到数值 7 时，先计算还需要 9−7=2，再到表里找 2。若找到，就把那个旧下标和当前位置一起返回；没找到，才把当前值及其下标加入表。查找在插入之前，因此不会把当前位置拿来与自己配对。

输出为 0 1。std::vector<int> 是存放整数的可增长序列，nums[i] 读取第 i 个元素，size() 给出元素数。长度转换为 int 在这里依据题目的一万上限成立，不应把这个转换机械复制到可能拥有更大输入的程序里。

std::unordered_map<long long,int> 把数值映射到下标。find 返回一个迭代器，和 end() 相等表示没找到；找到后，found->second 才是已保存的下标。try_emplace（C++17）在键不存在时插入，存在时保留先前的位置。return {a,b} 创建并返回含两个下标的 vector。

need 先把目标转换成 long long 再相减，使中间计算在较宽的整数类型中进行。仅仅把 int 运算的结果赋给 long long，不会补救此前已经发生的溢出。哈希表一次操作平均为常数级，本算法平均时间 O(n)、额外空间 O(n)；不把平均表现承诺成所有输入下的最坏保证。

两个会悄悄改变答案的顺序

对 [3,2,4]、目标 6，如果先把第一个 3 加入表，再检查还需要的 3，就会错误地拿下标 0 配自己。正确的“先找、后存”避免了这件事；[3,3] 则会在第二个位置找到第一个 3，正确返回两个不同下标。

查找也不要写成“读取 seen[need] 再判断”。operator[] 会在键缺失时插入默认值；下标 0 又恰好是合法位置，容易把“未找到”和“在第一个位置”混在一起。用 find 同时取得“是否存在”和“保存的下标”，判断就明确了。

表是方法里的局部变量，每次调用重新建立。平台可能多次调用你的解法；把上一题或上一个样例的记录留在成员变量、全局数组里，是“单独运行通过，连着运行失败”的常见来源。返回空数组只是本地防御分支；官方题目的有效输入保证应当能找到解。

把最常用的几种操作练到不用猜

写题先选能表达操作目标的容器，而不是先把所有东西放进同一种结构。下面的头文件应由本地程序明确包含；bits/stdc++.h 是部分工具链的扩展，跨平台学习代码不依赖它。

目标常用类型与头文件常见操作与边界
连续序列、按下标访问std::vector<T>，<vector>push_back 末尾追加通常摊还 O(1)；reserve 不创建元素，访问位置必须小于 size()
字符串std::string，<string>size() 统计字符单元；UTF-8 中文不能直接把字节数当汉字数
按键查找或去重std::unordered_map／unordered_set，对应同名头文件查找平均 O(1)；只查是否存在可用 contains（C++20），还要取值时用 find
需要键有序std::map／set，<map>／<set>查找与插入为 O(log n)；不要把有序输出误归因给哈希表
先进先出std::queue<T>，<queue>push 入队，front 看队首，pop 移除且不返回值；读队首前先判断 empty()
每次取最大值std::priority_queue<T>，<queue>默认最大值在 top；插入、移除通常 O(log n)，查看前先判空

std::accumulate 定义在 <numeric>，从给定初值开始累加。0LL 使本例用 long long 保存中间和；如果初值写成 0，累加器就是 int。较宽类型也有范围上限，仍要根据题目给出的元素数量和值域估计总和。

换到标准输入输出题，算法外面再包一层入口

假设题面约定第一项是数量 n，后面有 n 个整数，输出它们的和。这里限定 0≤n≤100000、每项绝对值不超过十亿，因此和的绝对值不超过十的十四次方，long long 足够。

保存为 judge_sum_input.cpp，编译后执行 printf '4\n2 -3 5 8\n' | ./judge_sum_input，输出 12。本地如果输入不足或越过约定范围，程序返回非零且不打印一个看起来有效的和；正式写题时，具体输入保证以题面为准。

开头两行适用于这里的非交互式输入：关闭 C 与 C++ 标准流之间的同步，并解除 cin 读取前对 cout 的自动刷新关联。应在任何输入输出之前设置，此后不要混用 scanf／printf 读写同一套输入输出流。交互题需要按协议主动刷新输出，不照搬离线题的习惯。

如果题目按行读取文本，使用 std::getline；若先用 >> 读数字再切到 getline，还要处理留在流中的换行。不要简单加一次“读空行”去碰运气，具体边界可回看流与可靠输入。

提交之前，用边界检查自己的推理

先让官方样例通过，再挑能打破当前假设的输入。两数之和至少看重复值 [3,3]、含负数、结果涉及第一个或最后一个位置；二分查找看空序列、目标小于全部值和大于全部值；求和看 n=0、负数和接近总和上限。调试越界时可在本地启用 AddressSanitizer 与 UndefinedBehaviorSanitizer，代价是额外运行开销。

运行时错误先定位非法访问或未定义行为，答案错误先找能手算的反例，超时再估算循环次数、容器操作和额外复制。单看一次运行时间，无法判断算法复杂度是否适合输入上限。

小结：够用的 C++，服务于清楚的解法

先确认提交接口，再用容器表达“要保存什么、怎样查找”，最后验证整数范围、空容器、位置有效性和多次调用。新语法能减少样板，但它不会替你决定“两个下标必须不同”这类题目条件。把一份能在本地重复运行的解法留下来，比积累一页没有边界说明的模板更有用。
