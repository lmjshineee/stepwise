这类负责构造、赋值和析构的函数统称特殊成员函数（Special Member Functions，SMFs）。先理解它们对对象做什么，再看具体签名和生成条件。

零法则：让成员类型管理资源

优先让资源交给标准库类型管理：

如果成员都能正确管理自己，类通常不需要手写任何 SMF。

零法则（Rule of Zero）是设计建议：把资源交给合适的成员类型管理，通常就不需要手写复制、移动或析构。它不保证所有类都能复制；还要看成员是否允许复制。

成员独占资源时，整个类也不能随意复制

把成员换成 std::unique_ptr<int>，它只允许一个指针对象承担删除责任。默认复制需要复制每个成员，而 unique_ptr 禁止复制，因此外层类的默认复制也不可用。移动则可以把责任交给新对象。

显式写出允许和禁止的操作

手写一个析构，也会改变隐式生成条件

六种特殊成员包括默认构造、复制构造、复制赋值、移动构造、移动赋值和析构。对于上面的简单类，编译器可以逐成员生成合适的操作；加入用户声明后要重新检查规则。

在本文 C++23 基线中，只有没有用户声明的复制构造、复制赋值、移动赋值和析构时，才隐式声明移动构造。移动赋值也要求没有用户声明的复制构造、移动构造、复制赋值和析构。即便显式写 ~T() = default，它仍是用户声明的析构，会影响隐式移动。默认实现还可能因为某个成员不支持相应操作而被删除。

判断时分两步：是否声明了移动操作，以及成员能否支持该操作；写 = default 不是绕过被删除成员的办法。移动构造与移动赋值自 C++11 引入，默认化与删除函数也自 C++11 引入。

选读：把对象操作对应到六种签名

现在把前面看到的对象行为对应到函数签名，再比较初始化写法。

C++ 为六类对象操作规定特殊成员函数。编译器在满足生成规则时提供其中一部分，成员和基类的限制还可能使默认操作被删除：

  • default constructor 默认构造函数
  • copy constructor 拷贝构造函数
  • copy assignment operator 拷贝赋值运算符
  • destructor 析构函数
  • move constructor 移动构造函数
  • move assignment operator 移动赋值运算符

返回较大对象如何经过寄存器或隐藏结果地址传递，取决于平台的调用约定和类型性质。理解 C++ 对象语义时，先看对象何时构造、移动和销毁；不能仅凭“返回结构体”断言它一定被复制到调用者栈上。

如果成员本身能正确管理资源，优先采用零法则，让编译器生成操作。必须直接管理裸资源时，复制构造、复制赋值与析构需要保持同一所有权策略；再加入移动操作时，统一检查五个操作对源对象和目标对象的影响。

六个特殊成员函数

选读：检测可构造，不等于检测移动函数存在

默认构造、析构、复制构造、复制赋值、移动构造、移动赋值是六个特殊成员。用户声明了其他构造函数后，不再自动提供无参默认构造；可以显式 = default。默认生成也可能因成员或基类的限制被删除。

用户声明复制操作或析构等会影响隐式移动生成。is_move_constructible 为 true 也不意味着类一定有移动构造：一个能接受右值的复制构造同样可以让检测成立。

选读：裸资源、异常保证与容器选择

选读：直接管理裸资源时统一五个操作

复制一个拥有裸指针的对象，默认逐成员复制会让两者保存同一地址；若两者都析构释放，就 double delete。深拷贝要新建资源并复制内容；复制赋值还需处理原有资源、自赋值和失败路径。

复制并交换（copy-and-swap）先构造完整临时副本，成功后用不抛的 swap 提交；复制失败时原对象不变，临时资源由析构清理。手写移动通常用 std::exchange（C++14，<utility>）转移指针并清空源状态，移动赋值还要释放目标旧资源。下面的 Buffer 示例将这些策略放到同一个资源类中。

选读：noexcept、析构与容器行为

容器重分配时，可用且不抛的移动更有利于保持异常保证；移动可能抛且复制可用时，容器可能选择复制。不可复制类型仍可能移动，所以“未写 noexcept 就绝不移动”不成立。

T b = a 在声明中是复制初始化，可能调用复制构造；已经存在的 b 才是赋值。vector<int> v(); 是函数声明；return T{}; 在 C++17 的规定情形保证省略复制，返回命名局部对象的 NRVO 则仍有条件。不要用构造日志推断所有编译器都必须执行同样次数。

noexcept 与容器

移动构造函数如果是 noexcept，标准容器在扩容时更愿意移动元素，否则可能退回拷贝以维持异常安全。

析构函数

  • 析构函数负责释放对象拥有的资源。
  • 基类用于多态删除时，析构函数应为 virtual。
  • 析构函数不应抛出异常。

逐个判断生成条件与资源语义

检查特殊成员函数（SMFs）时，先列出用户已声明的构造、复制、移动与析构，再检查每个成员是否支持目标操作，最后核对默认逐成员操作是否符合业务所有权。接口存在与操作正确是两个不同判断。

快速判断

  • 没有资源所有权：Rule of Zero。
  • 独占资源：常见策略是禁止复制、允许移动；若业务要求复制，必须建立独立资源。
  • 值语义资源：实现深拷贝和 noexcept 移动。
  • 多态基类：通常删除复制，提供 virtual destructor。

小结：先定资源策略，再查生成条件

判断构造还是赋值，先看目标对象是否已经存在；判断能否复制或移动，再看成员支持什么，以及用户声明改变了哪些隐式生成条件。= default 不能绕过成员的限制，类型特征成立也不代表一定调用了某个移动函数。

优先把资源交给能自行管理的成员，让默认操作组合行为。确需直接管理裸资源时，再统一设计复制、移动和清理，并检查失败路径、自赋值和来源状态；三个或五个操作是一套所有权策略，不是几个孤立签名。
