迭代器、指针与算法的能力要求

理解半开区间、迭代器类别和失效规则，按算法需要选择遍历方式。

课程C++CS106LC++23知识点迭代器算法C++23

先走过三个元素，再到尾后位置

容器保存元素，迭代器表示访问位置。对 vector<int>{2,4,6}，begin位于2，end位于6之后的边界。解引用 *it取得当前位置的元素；前置递增 ++it移到下一个位置。end不是第四个元素，只能在这个循环中用来比较是否结束，不能读取它。

图1：三元素vector的半开区间与循环步骤。实线框是已有元素，右侧虚线是尾后边界；“到达end”与“读取end”是不同操作。

预期输出：

检查时的位置it != end循环体递增后的位置
元素2真读取2元素4
元素4真读取4元素6
元素6真读取6end
end假不进入，不解引用不递增

这就是半开区间 [begin,end)：包含起点元素，排除尾后边界。空容器的begin已经等于end，循环一次也不进入。范围for同样先比较、再解引用、再递增；循环变量写值还是引用，决定是否修改原元素。

迭代器类别决定算法能否使用

先比较两种具体容器。vector迭代器支持 begin()+1 直接到第二个元素；list迭代器可以前后移动，但不能直接加整数。排序也要匹配能力：std::sort要求随机访问迭代器，list使用自己的成员函数sort。

预期输出：

两者的逻辑顺序都变成2、4、6，但位置操作不同。不能因为list的第二个元素存在，就推断 linked.begin()+1 合法。

std::ranges::sort(contiguous) 是 C++20 的整容器接口，仍要求随机访问和可排序元素，没有放宽为“所有容器”。unordered_set 的迭代器至少提供前向遍历能力，不应当作双向迭代器；更不支持随机访问排序。

std::sort 需要随机访问迭代器，不能直接对 list 调用；list::sort 是成员算法。std::distance 对随机访问范围能直接求差，对链式范围通常要逐个递增。++it 表达递增且不索取旧值，it++ 还要表达旧位置；是否产生实际性能差异要测量。

区分元素只读与位置不可修改

指针是保存地址的对象。&value 取得 value 的地址，*pointer 访问所指对象；nullptr（C++11）表示空指针。空指针不能解引用，指向已经结束寿命的对象也不能解引用。

预期输出：

const int* 限制通过指针修改整数；int* const 限制指针变量改指向，仍可修改所指的可写整数。把 pointer 设为空不会删除 value；这里的指针只是借用，value 仍由所在作用域管理。

const_iterator 限制通过它修改元素，通常仍可以递增位置；const iterator 限制迭代器变量自身，未必限制所指元素。指针也可满足迭代器协议，某些实现把 vector 的迭代器包装成检查对象，不能假设其具体类型一定是 T*。

裸指针运算同样受边界约束，只能在同一数组对象及其尾后位置内移动和求差。别把“地址是数值”误解为可以任意算术和访问。容器修改后是否继续有效，回看 失效表。

选读：迭代器操作与表示速查

迭代器支持哪些操作取决于类别。list 和 map 的迭代器不支持加减整数或计算距离差；指针也可以充当迭代器。vector::iterator 的具体表示由标准库实现决定。

要访问容器中的对象，除了用下标运算符，也可以使用 iterator（迭代器）实现。而且，大部分标准库容器都支持迭代器（除了 stack 和 queue 以外），但是只有少数几种还同时支持下标运算符。

对一个容器对象，我们可以用 begin 和 end 获得迭代器。begin 指向第一个元素，end 指向最后一个元素的下一个位置。

下列是不同类别可能支持的操作集合，不是每个迭代器都支持全部：-- 需要双向能力，+、-、距离差和顺序比较需要随机访问能力。

迭代器是满足特定操作要求的类型，可能是指针，也可能是包装对象。程序应使用容器公开的迭代器类型：

const_iterator 限制经它修改元素，iterator 是否可写仍取决于容器：例如 set 的键不能通过迭代器修改，以免破坏排序不变量。

包装迭代器可以保存容器身份或检查信息；标准不要求所有容器采用这种表示，也不保证 vector::iterator 必为 T*。

指针递增可以遍历同一数组中的元素；非连续容器的迭代器递增则遵循容器的逻辑顺序，不一定对应地址相加。具体保存哪些状态由实现决定，不能由接口反推其一定比指针存更多信息。

迭代器推广了指针的遍历接口；这是对可用操作的抽象，不是对物理表示的保证。

小结：先核对位置，再核对能力

迭代器描述的是容器中的位置，尾后位置只作边界，不能解引用。算法能否使用，先看它要求哪些位置操作，再看容器是否提供；逻辑上存在第二个元素，不代表可以写 begin()+1。

写入算法还要有合法目标：覆盖已有元素与通过 back_inserter 追加是两种过程，预留容量不能代替创建元素。最后分别检查元素是否只读、位置变量能否移动，以及容器修改后旧位置是否仍然有效。
